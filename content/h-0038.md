## 結論：同じポートを別のプロセスがすでに使っています。そのプロセスを止めるか、別のポートで起動すると直ります

`Error: listen EADDRINUSE: address already in use 0.0.0.0:3000` は、「3000番ポートはもう別のプログラムが使っているので、このサーバーは待ち受けできない」というエラーです。前に起動したサーバーが裏で動いたまま、もう一度起動したときによく起きます。
直し方は、`lsof -i :3000` で使っているプロセスの番号（PID）を調べて `kill` で止めるか、`PORT=3001 node server.js` のように別のポートで起動することです。
この環境では、どちらの方法でもサーバーが起動し、ブラウザの代わりに `curl` でアクセスして応答が返ることを確認しました。

```text 実行ログ
$ lsof -i :3000
COMMAND PID   USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
node    387 ubuntu   21u  IPv4   4405      0t0  TCP *:3000 (LISTEN)

$ kill 387
```

## 検証環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 24.04.5 LTS |
| Node.js | Node.js v22.23.5 |

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。たとえば IPv6 が有効な環境では、エラー文の最後が `0.0.0.0:3000` ではなく `:::3000` と表示されることがあります。どちらも意味は同じです。

## エラーの再現：サーバーを2回起動する

Node.js で Web サーバーを作って動作確認していると、ターミナルを閉じたつもりでも前のサーバーが動いたままになっていることがあります。その状態でもう一度起動すると、このエラーになります。Express など、ほかのフレームワークでも中で同じ仕組み（`listen`）を使っているので、同じエラー文が出ます。

ここでは、3000番ポートで待ち受ける最小のサーバー `server.js` を用意しました。

```text 実行ログ
$ cat server.js
const http = require("http");

const port = 3000;

const server = http.createServer((req, res) => {
  res.end("Hello from port " + port + "\n");
});

server.listen(port, () => {
  console.log(`Server running at http://localhost:${port}/`);
});
```

まず1つ目のサーバーを裏で（`&` を付けて）起動しました。こちらは正常に起動しています。

```text 実行ログ
$ node server.js > first.log 2>&1 &

$ cat first.log
Server running at http://localhost:3000/
```

この状態で、もう一度同じファイルを起動すると、次のエラーで止まりました。

```text 実行ログ
$ node server.js
node:events:497
      throw er; // Unhandled 'error' event
      ^

Error: listen EADDRINUSE: address already in use 0.0.0.0:3000
    at Server.setupListenHandle [as _listen2] (node:net:1941:16)

    at Server.listen (node:net:2103:7)

    at Module._compile (node:internal/modules/cjs/loader:1781:14)
    at Object..js (node:internal/modules/cjs/loader:1913:10)
    at Module.load (node:internal/modules/cjs/loader:1505:32)
    at Function._load (node:internal/modules/cjs/loader:1309:12)
    at wrapModuleLoad (node:internal/modules/cjs/loader:254:19)
    at Function.executeUserEntryPoint [as runMain] (node:internal/modules/run_main:171:5)

```

エラー文の読み方は次のとおりです。

- `Error: listen EADDRINUSE: address already in use 0.0.0.0:3000` が本体です。`listen`（待ち受けの開始）のときに、`EADDRINUSE`（アドレスが使用中）になった、という意味です。最後の `:3000` がぶつかったポート番号です。
- `server.js:9:8` は、自分のコードのうちエラーにつながった場所です。9行目の `server.listen(port, ...)` を指しています。コードの書き間違いではなく、「待ち受けを始めようとしたら先客がいた」ということです。
- 下の `code: 'EADDRINUSE'` と `port: 3000` は、エラーの種類とポート番号をもう一度まとめて表示したものです。
- 一番上の `Unhandled 'error' event` は、このエラーを受け取る処理（`error` イベントの処理）を書いていないため、プログラム全体が止まったことを表しています。

## 原因：前に起動したサーバーが3000番ポートを使ったままになっている

1つのポートで待ち受けられるのは、基本的に1つのプロセスだけです。Node.js の公式ドキュメント（Errors の「Common system errors」）でも、`EADDRINUSE` は「ローカルのアドレスにサーバーを結び付けようとしたが、別のサーバーがすでにそのアドレスを使っている」ときのエラーとして説明されています。

本当に別のプロセスが3000番を使っているのかを、`lsof` で確かめました。`-i :3000` は「3000番ポートを使っているもの」を表示するオプションです。

```text 実行ログ
$ lsof -i :3000
COMMAND PID   USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
node    387 ubuntu   21u  IPv4   4405      0t0  TCP *:3000 (LISTEN)
```

`COMMAND` が `node`、`PID` が `387`、最後が `(LISTEN)`（待ち受け中）になっています。最初に裏で起動したサーバーが、3000番を使い続けていることが分かりました。PID の数字は実行するたびに変わるので、ご自分の環境で表示された数字を使ってください。

## 直し方1：使っているプロセスを止めてから起動し直す

前のサーバーが不要なら、`kill` に PID を渡して止めます。止めたあと、もう一度 `lsof` を実行すると、何も表示されなくなりました（3000番を使っているものがない）。

```text 実行ログ
$ kill 387

$ lsof -i :3000
```

この状態でサーバーを起動し、`curl` でアクセスしました。今度はエラーにならず、サーバーからの応答が返りました。

```text 実行ログ
$ node server.js & sleep 1; curl -s http://localhost:3000/; kill %1
Server running at http://localhost:3000/
Hello from port 3000
```

なお、前のサーバーを起動したターミナルが手元に残っているなら、そのターミナルで `Ctrl + C` を押して止めるのがいちばん簡単です。`kill` は、どのターミナルで起動したか分からなくなったときに使います。

## 直し方2：別のポートで起動できるようにしておく

前のサーバーを止めたくない場合（別のアプリが3000番を使っている場合など）は、別のポートで起動します。ポート番号をコードに直接書かず、環境変数 `PORT` から読むようにしておくと、起動のたびに番号を変えられます。あわせて `error` イベントを受け取り、ポートが使用中のときは分かりやすいメッセージを出して終了するようにしました。

```text 実行ログ
$ cat server.js
const http = require("http");

const port = process.env.PORT || 3000;

const server = http.createServer((req, res) => {
  res.end("Hello from port " + port + "\n");
});

server.on("error", (err) => {
  if (err.code === "EADDRINUSE") {
    console.error(`ポート ${port} は使用中です。PORT=3001 node server.js のように別のポートを指定してください。`);
    process.exit(1);
  }
  throw err;
});

server.listen(port, () => {
  console.log(`Server running at http://localhost:${port}/`);
});
```

3000番を別のサーバーが使っている状態で、そのまま起動すると、長いエラーの代わりに用意したメッセージが表示されました。

```text 実行ログ
$ node server.js
ポート 3000 は使用中です。PORT=3001 node server.js のように別のポートを指定してください。
```

メッセージのとおり `PORT=3001` を付けて起動すると、3001番で起動し、アクセスにも応答しました。

```text 実行ログ
$ PORT=3001 node server.js & sleep 1; curl -s http://localhost:3001/; kill %1
Server running at http://localhost:3001/
Hello from port 3001
```

`process.env.PORT || 3000` は、「環境変数 `PORT` があればその値、なければ3000」という意味です。レンタルサーバーやクラウドの公開先では、使うポートを環境変数 `PORT` で渡してくることが多いので、この書き方にしておくと公開するときにも書き換えずに済みます。

## うまくいかないとき

- **ターミナルを閉じたのにポートが空かない場合**は、`&` で裏で起動したサーバーが残っています。この記事の再現手順と同じ状態なので、`lsof -i :3000` で PID を調べて `kill` してください。
- **Windows の場合**は `lsof` がありません。この記事では Windows では実行して確かめていないため、ポートとプロセスの関係はお使いの OS の公式ドキュメントをご確認ください。Node.js 側の考え方（同じポートは1つのプロセスしか使えない、`PORT` で変えられるようにしておく）は同じです。
- `listen` の引数や `error` イベントの詳しい動きは、Node.js 公式ドキュメントの「server.listen()」をご確認ください。

## まとめ

`Error: listen EADDRINUSE: address already in use` は、起動しようとしたポートを別のプロセスがすでに使っているときに出るエラーです。この環境では、前に起動したサーバーが3000番を使ったままになっていたのが原因で、`lsof -i :3000` で PID を調べて `kill` すると起動できるようになりました。止めたくない場合は、ポートを `process.env.PORT` から読むようにして `PORT=3001 node server.js` のように別のポートで起動できることも確認しました。
