## 結論：HTML → CSS → JavaScript の順に1枚のページを作り、そのあと Node.js と npm、Git へ進みます

Web制作の独学は、HTMLで中身の構造を書き、CSSで見た目と配置を整え、JavaScriptで動きを付ける、という順番で進めるのが基本です。3つを別々に学ぶよりも、自分で決めた1枚のページ（自己紹介ページや、好きなお店の紹介ページなど）を少しずつ育てながら学ぶほうが、何のための知識なのかが分かりやすくなります。

ページが形になったら、Node.js と npm を使った開発の道具に進み、最後に Git で変更を記録して、公開できる状態にします。この記事では全体を5つのステップに分け、各ステップで「できるようになること」「つまずきやすい所」「このサイトの手順記事」を並べました。手順記事がまだない段階は、公式のドキュメント（MDN Web Docs など）にリンクしています。

## ステップ1：HTMLでページの構造を書く

HTMLは、ページの中身が「見出しなのか」「段落なのか」「リンクなのか」を、タグで表すための言語です。最初は、テキストエディタで `index.html` という名前のファイルを作り、ブラウザで開いて表示を確かめる、という往復を繰り返します。特別な道具は必要なく、ブラウザとエディタがあれば始められます。

この段階でつまずきやすいのは、見た目を整えるためにタグを選んでしまうことです。たとえば文字を大きくしたいだけなのに見出しのタグを使うと、検索エンジンや読み上げソフトにとって分かりにくいページになります。見た目はステップ2のCSSに任せ、HTMLでは「意味に合ったタグを選ぶ」ことに集中すると、後の作業がずっと楽になります。閉じタグの書き忘れや、画像のファイル名とパスの食い違いもよくある原因です。表示が崩れたら、ブラウザの開発者ツールで、要素が思った場所に入っているかを確かめる習慣をつけましょう。

- つまずきやすい所: 閉じタグの書き忘れ、画像やリンクのパスの間違い、見た目のためのタグ選び
- 公式ドキュメント: https://developer.mozilla.org/ja/docs/Web/HTML 、https://developer.mozilla.org/ja/docs/Learn_web_development

## ステップ2：CSSで見た目と配置を整える

CSSは、HTMLで書いた要素に色・文字の大きさ・余白・配置を指定するための言語です。最初は文字の色や背景色、余白（margin と padding）の違いを確かめるところから始め、慣れてきたら Flexbox と Grid を使って要素を横に並べたり、画面の幅に合わせて並び方を変えたりする方法に進みます。

CSSで多くの人が迷うのは、「指定したのに反映されない」場面です。原因は、セレクタの書き間違い、同じ要素に別の指定が後から上書きしている、親要素の設定が影響している、などさまざまです。ここでも開発者ツールが役に立ちます。要素を選ぶと、どの指定が効いていて、どれが打ち消されているかが一覧で表示されるので、当てずっぽうに書き足す前に、まずそこを見るようにします。スマートフォンでの見え方も、開発者ツールの表示幅の切り替えで確かめられます。

- つまずきやすい所: 指定の上書き（詳細度と書く順番）、margin と padding の違い、Flexbox と Grid の使い分け
- 公式ドキュメント: https://developer.mozilla.org/ja/docs/Web/CSS

## ステップ3：JavaScriptでページに動きを付ける

JavaScriptは、ページを読み込んだあとに表示を変えたり、ボタンのクリックや入力に反応したりするための言語です。まずは、ボタンを押したらメニューを開く、入力した文字を画面に表示する、といった小さな動きを、ステップ1と2で作ったページに1つずつ足していきます。HTMLの要素を JavaScript から取り出して書き換える操作（DOM 操作）が、Web制作でのJavaScriptの中心になります。

この段階でよく出会うのが、`TypeError: Cannot read properties of undefined` というエラーです。取り出したつもりの要素やデータが実際には存在せず、undefined のまま中身を読もうとしたときに起きます。このサイトの手順記事では、このエラーをわざと起こし、どの値が undefined になっているかを確かめてから直す手順を、実際に実行して確認しています。エラーが出たら、ブラウザの開発者ツールのコンソールで、エラー文と行番号を読むことから始めましょう。

- つまずきやすい所: [JavaScriptで TypeError: Cannot read properties of undefined (reading 'xxx') が出たときの原因と直し方](/h-0037/)
- 公式ドキュメント: https://developer.mozilla.org/ja/docs/Web/JavaScript

## ステップ4：Node.js と npm で開発の道具を使う

ページ作りに慣れてくると、ライブラリを使ったり、ファイルをまとめて変換したり、開発用のサーバーで変更をすぐに確かめたりしたくなります。そのときに使うのが、ブラウザの外で JavaScript を動かす Node.js と、パッケージを管理する npm です。`npm install` でパッケージを入れ、`package.json` に書かれたコマンドを `npm run` で動かす、という流れを覚えるのがこのステップの目標です。

ここでは、HTMLやCSSとは違う種類のエラーが増えます。パッケージ同士の求めるバージョンが合わずに `npm install` が ERESOLVE で止まる、`npm install -g` が権限不足の EACCES で止まる、といったものです。また JavaScript には、ファイルの読み込み方に `import` と `require` の2つの書き方があり、設定と書き方が合っていないと SyntaxError や ReferenceError になります。どれも、このサイトの手順記事でエラーを再現し、直ることを確かめています。

- つまずきやすい所: [npm install で ERESOLVE unable to resolve dependency tree が出たときの原因と直し方](/h-0033/)、[npm install -g で EACCES: permission denied が出たときの原因と直し方](/h-0034/)、[Node.jsで SyntaxError: Cannot use import statement outside a module が出たときの原因と直し方](/h-0905/)、[Node.jsで ReferenceError: require is not defined in ES module scope が出たときの原因と直し方](/h-0036/)
- 公式ドキュメント: https://nodejs.org/en/learn/getting-started/introduction-to-nodejs 、https://docs.npmjs.com/about-npm

## ステップ5：Git で記録し、公開できる状態にする

作ったページを人に見てもらうには、ファイルをサーバーに置いて公開する必要があります。その前に身につけておきたいのが Git です。Git で変更を記録しておけば、表示が崩れたときに動いていた時点へ戻れますし、GitHub などのリモートのリポジトリにファイルを置けば、そこから公開する仕組みにもつなげられます。最初は、作業フォルダで `git init` を実行し、区切りのよいところで commit する、という最小限の使い方で十分です。

手元とリモートでそれぞれ別に履歴を作ってしまうと、`git pull` が refusing to merge unrelated histories で止まることがあります。このエラーが出る仕組みと直し方も、手順記事で再現して確かめています。

- つまずきやすい所: [git pull で fatal: refusing to merge unrelated histories が出たときの原因と直し方](/h-0904/)
- 公式ドキュメント: https://git-scm.com/book/ja/v2
