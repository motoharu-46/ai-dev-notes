## 結論：環境づくり → 文法とエラーの読み方 → ファイル操作 → モジュール分け → pandas → スクリプト化の順に進めます

業務自動化で使うPythonは、「決まった場所のファイルを読み、集計や変換をして、別のファイルに書き出す」処理が中心です。そのため、文法をひととおり覚えたら早めにファイルとパスの扱いに進み、そのあとで表データを扱う pandas を学ぶ順番にすると、途中で目的を見失いにくくなります。最初の一歩は、仮想環境（venv）を作ってその中でパッケージを入れられるようにすることです。

この記事では、学ぶ内容を6つのステップに分け、それぞれで「できるようになること」「つまずきやすい所」「参考になる公式ドキュメント」を並べました。つまずきやすい所には、このサイトで実際にエラーを再現し、直し方を実行して確かめた手順記事をつないでいます。エラーが出たときに、そのステップに戻って読み返す使い方を想定しています。

## ステップ1：環境を用意する

Pythonを入れたら、まず作業用のフォルダごとに仮想環境（venv）を作る方法を覚えます。業務自動化では pandas や Excel を扱うライブラリなど、標準ライブラリ以外のパッケージを使う場面が多く、仮想環境を使うと、プロジェクトごとに入れたパッケージが混ざらずに済みます。

ここでよく起きるのが、「pip install したのに import できない」という食い違いです。原因の多くは、パッケージを入れた Python と、スクリプトを実行している Python が別物であることです。また Ubuntu 24.04 などでは、仮想環境の外で pip install を実行すると、OSのPythonを守るためにエラーで止められます。どちらも venv を作って有効にし、その中で入れ直すことで解決できることを、手順記事で確かめています。

- つまずきやすい所: [Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv）](/h-0902/)、[pip install で error: externally-managed-environment が出たときの原因と直し方（Ubuntu 24.04）](/h-0903/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/venv.html

## ステップ2：文法とエラー文の読み方

変数、リストと辞書、if 文、for 文、関数の定義までを、公式チュートリアルの順に進めます。業務自動化で使う処理の多くは、この範囲の組み合わせで書けます。クラスやデコレーターなどは、必要になった時点で戻ってくれば十分です。

この段階で身につけておきたいのが、エラー文（トレースバック）の読み方です。最後の行にエラーの種類と説明があり、その少し上に、エラーが起きたファイル名と行番号が出ます。日本語の入力に慣れていると、全角スペースが紛れ込んで SyntaxError になったり、インデントの揃え方で IndentationError になったりします。また、関数が値を返し忘れて None になり、それを添字で読もうとして TypeError になるのも、初めのうちに出会いやすいエラーです。

- つまずきやすい所: [Pythonで SyntaxError: invalid non-printable character U+3000 が出たときの原因と直し方（全角スペース）](/h-0004/)、[Pythonで IndentationError: unexpected indent が出たときの原因と直し方](/h-0005/)、[Pythonで TypeError: 'NoneType' object is not subscriptable が出たときの原因と直し方](/h-0006/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/index.html 、https://docs.python.org/ja/3/tutorial/errors.html

## ステップ3：ファイルとパスの扱い

業務自動化の入口は、ファイルを読むことと書くことです。open() でテキストを読み書きする方法と、with 文でファイルを閉じ忘れない書き方を覚えたら、pathlib でパスを組み立てる方法に進みます。

ここでつまずきやすいのは、「ファイルはあるのに FileNotFoundError になる」場面です。相対パスは、スクリプトの置き場所ではなく、実行したときの作業フォルダを基準に解決されるため、実行する場所を変えただけで見つからなくなります。また、Windows の Excel などで作った日本語のCSVは Shift_JIS 系の文字コードで保存されていることがあり、そのまま読むと UnicodeDecodeError になります。どちらも、このサイトの手順記事で再現と解決を確かめています。

- つまずきやすい所: [Pythonで FileNotFoundError: [Errno 2] No such file or directory が出たときの原因と直し方（相対パスと実行場所）](/h-0009/)、[Pythonで UnicodeDecodeError: 'utf-8' codec can't decode byte が出たときの原因と直し方（日本語CSV）](/h-0901/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/inputoutput.html 、https://docs.python.org/ja/3/library/pathlib.html

## ステップ4：コードを複数ファイルに分ける

処理が増えてくると、1つのファイルに全部を書くと読みにくくなります。よく使う関数を別のファイル（モジュール）に移し、import で呼び出せるようにすると、別の業務のスクリプトでも同じ関数を使い回せます。

このとき起きやすいのが、ファイルAがファイルBを import し、ファイルBもファイルAを import してしまう循環インポートです。エラー文に partially initialized module と出たら、import の向きが一方通行になっているかを確認します。また、自分で作ったファイルに標準ライブラリやパッケージと同じ名前（たとえば pandas.py）を付けると、そちらが先に読み込まれて思わぬエラーになるので、ファイル名の付け方にも気をつけます。

- つまずきやすい所: [Pythonで ImportError: cannot import name from partially initialized module（循環インポート）が出たときの原因と直し方](/h-0010/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/modules.html

## ステップ5：pandas で表データを扱う

CSVやExcelの集計・変換は、pandas を使うと短いコードで書けます。read_csv で読み込み、列を選び、条件で行を絞り込み、groupby で集計し、to_csv や to_excel で書き出す、という流れが基本形です。ステップ3で扱った文字コードの指定は、pandas の read_csv でも同じように必要になります。

pandas でつまずきやすいのは、「列はあるはずなのに KeyError になる」場面です。見出しの前後に空白が入っていたり、全角と半角が混ざっていたりすると、見た目は同じでも別の列名として扱われます。また、絞り込んだ結果に値を代入したときに出る SettingWithCopyWarning は、元のデータが変わらないまま処理が進むことがあるので、無視せずに .copy() や .loc を使った書き方に直しておくと安心です。

- つまずきやすい所: [pandasで KeyError: '列名' が出たときの原因と直し方（列は存在するのに）](/h-0007/)、[pandasで SettingWithCopyWarning が出たときの原因と消し方（.copy() と .loc）](/h-0008/)
- 公式ドキュメント: https://pandas.pydata.org/docs/getting_started/index.html

## ステップ6：業務で回せるスクリプトにする

最後に、書いた処理を「毎回同じ手順で動かせる道具」の形に整えます。入力ファイルや出力先をコードに直接書くのではなく、argparse でコマンドライン引数として受け取るようにすると、対象の月や部署が変わってもコードを書き換えずに実行できます。あわせて、ステップ1で作った venv と、使ったパッケージの一覧（requirements.txt など）を残しておくと、別のパソコンでも同じ環境を作り直せます。
