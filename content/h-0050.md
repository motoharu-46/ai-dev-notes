この記事の手順は 2026年11月27日 に下記の環境で実際に実行して確認しました。

## 結論：2つのブランチで同じ行が変わっているためです。マーカーを消して正しい内容に直し、git add と git commit で解消できます

`CONFLICT (content): Merge conflict in app.py` は、「マージしようとした2つのブランチが同じファイルの同じ場所を別々に変えているので、どちらを残すか Git だけでは決められません」という意味です。エラーで壊れたわけではなく、人の判断を待って一時停止している状態です。
直し方は、ファイルの中の `<<<<<<<`・`=======`・`>>>>>>>` で囲まれた部分を残したい内容に書き直し、`git add ファイル名` で「解消済み」と伝えてから `git commit` することです。
この環境では、この手順でマージが完了し、`git status` が `nothing to commit, working tree clean` に戻ることを確認しました。

```text 実行ログ
$ git add app.py && git status
On branch main
All conflicts fixed but you are still merging.
  (use "git commit" to conclude merge)

Changes to be committed:
	modified:   app.py
```

## 検証環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 24.04.5 LTS |
| Git | git version 2.43.0 |

`app.py`（あいさつを表示するだけの短い Python ファイル）を1つ置いたリポジトリで、`main` と `feature` の2つのブランチから同じ行を変える状況を作りました。後半では、同じパソコンの中に作ったリモート用のリポジトリ（`remote.git`）を GitHub の代わりに使い、`git pull` で衝突する場合も確かめています。お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

## エラーの再現：2つのブランチで同じ行を変えてからマージする

最初のコミットの `app.py` は次の内容です。

```text 実行ログ
$ cat app.py
def greet():
    print("Hello")

greet()
```

`feature` ブランチを作り、`print("Hello")` の行を `Hello, world` に変えてコミットしました。

```text 実行ログ
$ git switch -c feature
Switched to a new branch 'feature'

$ sed -i "s/Hello/Hello, world/" app.py && git commit -q -am "greet: Hello, world" && git log --oneline
9f8c9c7 greet: Hello, world
28e5bce Initial commit
```

次に `main` に戻り、同じ行を `こんにちは` に変えてコミットしました。`git log --graph` で見ると、最初のコミットから2本の枝に分かれています。

```text 実行ログ
$ git switch main
Switched to branch 'main'

$ sed -i "s/Hello/こんにちは/" app.py && git commit -q -am "greet: こんにちは" && git log --oneline --graph --all
* 9f8c9c7 greet: Hello, world
| * ac60e91 greet: こんにちは
|/  
* 28e5bce Initial commit
```

この状態で `main` に `feature` をマージすると、衝突しました。

```text 実行ログ
$ git merge feature
Auto-merging app.py
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.
```

要点は2行目と3行目です。「`app.py` の中身（content）で衝突した」「自動のマージに失敗したので、衝突を直してから結果をコミットしてください」と書かれています。

## 原因：同じ行を両方のブランチが別々に変えている

`git status` で、どのファイルが衝突しているかを確かめました。

```text 実行ログ
$ git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   app.py

no changes added to commit (use "git add" and/or "git commit -a")
```

`Unmerged paths` の下の `both modified: app.py` が、両方のブランチで変更されて衝突しているファイルです。ファイルを開くと、Git が書き込んだ印（コンフリクトマーカー）が入っていました。

```text 実行ログ
$ cat app.py
def greet():
<<<<<<< HEAD
    print("こんにちは")
=======
    print("Hello, world")
>>>>>>> feature

greet()
```

`<<<<<<< HEAD` から `=======` までが今いるブランチ（`main`）の内容、`=======` から `>>>>>>> feature` までがマージしようとしたブランチ（`feature`）の内容です。違う行どうしの変更なら Git が自動でまとめますが、同じ行の場合はどちらが正しいかを決められないため、両方を残して止まります。Git の公式ドキュメント（git-merge の「HOW TO RESOLVE CONFLICTS」）でも、この印を手で直す方法が説明されています。

## 直し方：マーカーを消して書き直し、git add と git commit をする

今回は両方の変更を活かして `こんにちは, world` にすることにして、マーカーの3行を消したファイルに書き直しました。エディタで開いて編集しても同じです。

```text 実行ログ
$ printf "def greet():\n    print(\"こんにちは, world\")\n\ngreet()\n" > app.py && cat app.py
def greet():
    print("こんにちは, world")

greet()
```

マーカーが残っていないことと、プログラムが動くことを確かめました。

```text 実行ログ
$ grep -n -E "^(<<<<<<<|=======|>>>>>>>)" app.py || echo "マーカーなし"
マーカーなし

$ python3 app.py
こんにちは, world
```

`git add` で「このファイルの衝突は解消した」と Git に伝えます。`git status` の表示が `All conflicts fixed but you are still merging.` に変わりました。

```text 実行ログ
$ git add app.py && git status
On branch main
All conflicts fixed but you are still merging.
  (use "git commit" to conclude merge)

Changes to be committed:
	modified:   app.py
```

最後に `git commit` でマージを完了させました。`--no-edit` は、Git が用意したマージのメッセージをそのまま使うオプションです。2つの枝がマージコミットでつながり、作業ツリーもきれいな状態に戻りました。

```text 実行ログ
$ git commit -q --no-edit && git log --oneline --graph
*   c1e82d9 Merge branch 'feature'
|\  
| * 9f8c9c7 greet: Hello, world
* | ac60e91 greet: こんにちは
|/  
* 28e5bce Initial commit

$ git status
On branch main
nothing to commit, working tree clean
```

## うまくいかないとき

- **いったんマージをやめて元に戻したい**ときは、`git merge --abort` を実行します。もう一度別の内容で衝突させてから実行したところ、マージ前の状態（`main` の `Good morning`）に戻りました。

```text 実行ログ
$ git merge feature
Auto-merging app.py
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.

$ git merge --abort && git status && cat app.py
On branch main
nothing to commit, working tree clean
def greet():
    print("Good morning")

greet()
```

- **どちらか一方の内容をそのまま採用したい**ときは、`git checkout --theirs ファイル名`（マージしてくる側）か `git checkout --ours ファイル名`（今いるブランチ側）が使えます。`--theirs` を実行したところ、`feature` 側の `Hi` だけが残り、そのまま `git add` と `git commit` でマージを完了できました。

```text 実行ログ
$ git merge feature > /dev/null; git checkout --theirs app.py && cat app.py
Updated 1 path from the index
def greet():
    print("Hi")

greet()

$ git add app.py && git commit -q --no-edit && git log --oneline -1
222f816 Merge branch 'feature'
```

- **git pull でも同じ衝突が起きます。** 別の作業場所（`pc-office`）が先に同じ行を変えて push したあとに、手元（`pc-home`）で `git pull --no-rebase` したところ、同じ `CONFLICT (content)` が出ました。直し方もこの記事と同じです。

```text 実行ログ
$ sed -i "s/Hi/Hello from office/" app.py && git commit -q -am "office edit" && git push -q origin main && git log --oneline -1
b10ea66 office edit

$ sed -i "s/Hi/Hello from home/" app.py && git commit -q -am "home edit" && git pull --no-rebase origin main
From /tmp/run-h-0050/work/remote
 * branch            main       -> FETCH_HEAD
   222f816..b10ea66  main       -> origin/main
Auto-merging app.py
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.
```

- **マーカーを消し忘れたまま git add してしまう**と、Git はそのまま受け付けます。コミットの前に `git diff --cached --check` を実行すると、残ったマーカーの行番号が `leftover conflict marker` として表示されました。直してから実行すると何も出なくなり、コミットと push ができました。

```text 実行ログ
$ git add app.py && git diff --cached --check
app.py:2: leftover conflict marker
app.py:4: leftover conflict marker
app.py:6: leftover conflict marker

$ printf "def greet():\n    print(\"Hello from office and home\")\n\ngreet()\n" > app.py && git add app.py && git diff --cached --check && echo "check ok"
check ok

$ git commit -q --no-edit && git push origin main
To /tmp/run-h-0050/work/remote.git
   b10ea66..65855a7  main -> main

$ git log --oneline --graph -3
*   65855a7 Merge branch 'main' of /tmp/run-h-0050/work/remote
|\  
| * b10ea66 office edit
* | 66b6b9b home edit
|/  
```

- リベース中（`git pull --rebase` や `git rebase`）の衝突では、`git add` のあとに `git commit` ではなく `git rebase --continue` を使います。この記事では実行していないため、手順は Git の公式ドキュメント（git-rebase）をご確認ください。
- そもそも `git push` が `! [rejected]` で通らない場合は、[git push で ! [rejected] main -> main (non-fast-forward) が出たときの原因と直し方](/h-0048/) をご覧ください。

## まとめ

`CONFLICT (content): Merge conflict in` は、2つのブランチが同じファイルの同じ行を別々に変えたときに、Git がどちらを残すか決められずに止まる表示です。この環境では、`git status` で衝突したファイルを確かめ、`<<<<<<<`・`=======`・`>>>>>>>` の部分を残したい内容に書き直してから `git add` と `git commit` をすると、マージが完了しました。やめたいときは `git merge --abort`、コミット前の確認には `git diff --cached --check` が使えます。
