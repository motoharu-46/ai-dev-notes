この記事の手順は 2026年11月6日 に下記の環境で実際に実行して確認しました。

## 結論：動かしているPythonと、モジュールを入れたPythonが別物です

「インストールしたのに `ModuleNotFoundError: No module named 'requests'` が出る」ときは、スクリプトを動かしているPythonに、そのモジュールが入っていません。仮想環境（venv）を使っている場合、パソコン全体のPythonに入れたモジュールは、仮想環境からは見えません。この環境では、仮想環境のPythonで `python -m pip install requests` を実行したところ、エラーが消えました。

```text 実行ログ
$ .venv/bin/python -m pip install requests 2>&1 | grep Successfully
Successfully installed certifi-2026.10.23 charset_normalizer-3.5.2 idna-3.20 requests-2.34.2 urllib3-2.8.0
```

## 検証環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 24.04.5 LTS |
| Python | Python 3.13.18 |
| requests | requests 2.34.2 |

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

## エラーの再現：パソコンでは動くのに、venvの中では動かない

requests を読み込んで、バージョンを表示するだけのスクリプトを用意しました。

```python
import requests

print("requests", requests.__version__)
```

パソコン全体のPython（`python3`）では、requests が入っているため動きます。

```text 実行ログ
$ python3 check_requests.py
requests 2.34.2
```

次に、同じフォルダに仮想環境 `.venv` を作り、仮想環境のPythonで同じスクリプトを動かしました。

```text 実行ログ
$ python3 -m venv .venv

$ .venv/bin/python check_requests.py
Traceback (most recent call last):
  File "/home/dev/work/venv-demo/check_requests.py", line 1, in <module>
    import requests
ModuleNotFoundError: No module named 'requests'
```

同じスクリプトなのに、仮想環境のPythonでは `ModuleNotFoundError` になりました。

## 原因：venvはパッケージを別に持っている

Pythonの公式ドキュメントでは、仮想環境は自分専用のパッケージの置き場所を持ち、パソコン全体のPythonに入っているパッケージとは分けて管理されると説明されています。作ったばかりの仮想環境に入っているパッケージを確かめると、pip しかありませんでした。

```text 実行ログ
$ .venv/bin/python -m pip list
Package Version
------- -------
pip     26.2.2
```

どのPythonが動いているかは、`sys.executable` で確かめられます。`python3` はパソコン全体のPython、`.venv/bin/python` は仮想環境のPythonで、別のものです。

```text 実行ログ
$ which python3
/usr/local/bin/python3

$ .venv/bin/python -c "import sys; print(sys.executable)"
/home/dev/work/venv-demo/.venv/bin/python
```

## 直し方：使うPythonに対して pip install する

仮想環境のPythonに `-m pip` を付けてインストールすると、確実にそのPythonに入ります。`pip` だけで実行すると、別のPythonの pip が動くことがあるためです。

```text 実行ログ
$ .venv/bin/python -m pip install requests 2>&1 | grep Successfully
Successfully installed certifi-2026.10.23 charset_normalizer-3.5.2 idna-3.20 requests-2.34.2 urllib3-2.8.0

$ .venv/bin/python check_requests.py
requests 2.34.2
```

エラーが消えました。仮想環境を有効にする `source .venv/bin/activate` を使う場合は、有効にした後の `python` が仮想環境のものになっていることも確かめました。

```text 実行ログ
$ source .venv/bin/activate && which python && python check_requests.py
/home/dev/work/venv-demo/.venv/bin/python
requests 2.34.2
```

## うまくいかないとき

- インストールしたのにまだエラーになる場合は、上の `sys.executable` の確認で、スクリプトを動かしているPythonのパスを表示してください。そのパスのPythonに `-m pip install` します。エディタ（VS Codeなど）から実行している場合は、エディタが選んでいるPythonが仮想環境のものかどうかもご確認ください。
- モジュール名とパッケージ名が違うことがあります（例: `import yaml` のパッケージ名は PyYAML）。名前は各パッケージの公式ドキュメントでご確認ください。
- Ubuntu 24.04 などで、パソコン全体のPythonに pip install しようとして `externally-managed-environment` というエラーが出る場合は、「[pip install で error: externally-managed-environment が出たときの直し方](/h-0903/)」をご覧ください。

## まとめ

`ModuleNotFoundError: No module named` は、動かしているPythonにモジュールが入っていないときのエラーです。仮想環境を使っているなら、仮想環境のPythonで `python -m pip install モジュール名` を実行すると、この環境では解決しました。
