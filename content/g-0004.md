## 結論：エラー文の最後の行から読み、原因の行と実行環境を確かめてから、小さく再現して調べます

エラーが出たときに、いきなりエラー文を丸ごと検索したり、思いついた書き換えを次々に試したりすると、原因が分からないまま時間だけが過ぎがちです。自力で解決するには、調べる順番を決めておくのが効果的です。このサイトでは、エラー解決の記事を書くたびに、同じ順番でエラーを再現し、直し方を実行して確かめています。

その順番は、①エラー文の最後の行で「種類」と「説明」を読む、②トレースバックから自分のコードの行を見つける、③どのPythonやNode.jsで、どのフォルダから実行したかを確かめる、④数行のコードで同じエラーを再現する、⑤公式ドキュメントとエラー文で調べる、⑥直ったことを再実行で確かめて記録する、の6つです。最初の一歩は、次にエラーが出たとき、画面のいちばん下の行だけを声に出して読んでみることです。

## 全体の順番

## ステップ1：エラー文の最後の行を読む

Pythonでエラーが起きると、トレースバックと呼ばれる数行から数十行のメッセージが出ます。長く見えても、いちばん大事なのは最後の行です。そこには `TypeError: 'NoneType' object is not subscriptable` のように、コロンの左にエラーの種類、右にその説明が書かれています。種類を見れば、文法の誤り（SyntaxError、IndentationError）なのか、値の型が想定と違う（TypeError）のか、名前が見つからない（NameError、ModuleNotFoundError）のか、といった大まかな分類ができます。

Node.js（JavaScript）でも考え方は同じで、`TypeError: Cannot read properties of undefined (reading 'name')` のように、種類と説明が1行にまとまって表示されます。説明の中にある `'name'` のような部分は、どのプロパティを読もうとして失敗したかを示す手がかりです。

- つまずきやすい所: 英語の説明を読み飛ばしてしまうことです。知らない単語があっても、エラーの種類の名前だけは公式ドキュメントの例外一覧で引くと、どんな場面で出るエラーかが分かります。
- このサイトの手順記事: [Pythonで SyntaxError: invalid non-printable character U+3000 が出たときの原因と直し方（全角スペース）](/h-0004/)、[Pythonで TypeError: 'NoneType' object is not subscriptable が出たときの原因と直し方](/h-0006/)、[JavaScriptで TypeError: Cannot read properties of undefined (reading 'xxx') が出たときの原因と直し方](/h-0037/)
- 公式ドキュメント: https://docs.python.org/ja/3/library/exceptions.html 、https://nodejs.org/api/errors.html

## ステップ2：原因の行を見つける

種類が分かったら、次は「どこで」起きたかです。Pythonのトレースバックは、呼び出しの古い順に `File "ファイル名", line 行番号` の形で並び、いちばん下がエラーが実際に起きた場所です。ライブラリの中のファイル名が並んでいることもありますが、まず探すのは自分が書いたファイルの名前が出ている行のうち、いちばん下にあるものです。たいていは、その行に渡した値が原因になっています。

行が見つかったら、その行で使っている変数の中身を `print()` で表示して確かめます。たとえば JSONDecodeError なら、読み込もうとした文字列が空だったり、JSONではなくHTMLだったりすることが、表示してみると分かります。RecursionError のように同じ行が何度も繰り返し表示されるトレースバックでは、繰り返しの部分が「終わらない呼び出し」を表しています。

- つまずきやすい所: IndentationError や SyntaxError では、表示された行番号の1行前に原因があることがあります。括弧やクォートの閉じ忘れは、次の行で初めてエラーとして見つかるためです。
- このサイトの手順記事: [Pythonで IndentationError: unexpected indent が出たときの原因と直し方](/h-0005/)、[Pythonで RecursionError: maximum recursion depth exceeded が出たときの原因と直し方](/h-0011/)、[Pythonで json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0) が出たときの原因と直し方](/h-0012/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/errors.html 、https://docs.python.org/ja/3/library/traceback.html

## ステップ3：実行環境を確かめる

コードに間違いが見当たらないのにエラーになるときは、実行している環境を疑います。よくあるのは、パッケージを入れたPythonと、コードを実行しているPythonが別物になっている場合です。`python3 --version` や `which python3`、`pip list` を実行すると、今どのPythonを使い、何が入っているかを確かめられます。仮想環境（venv）を作っているなら、有効にしてから実行しているかも確認します。

もう1つ多いのが、実行した場所（カレントディレクトリ）の違いです。`open("data.csv")` のような相対パスは、スクリプトの置き場所ではなく、実行したときのフォルダを基準に探されます。Node.js では `node --version` と `npm ls` で、使っているバージョンと入っているパッケージを確かめられます。

- つまずきやすい所: 権限のエラーを `sudo` を付けて押し切ろうとすることです。npm の EACCES や pip の externally-managed-environment は、環境を守るための仕組みが止めているので、仮想環境やユーザー用の置き場所を使う方法で直すほうが安全です。
- このサイトの手順記事: [Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv）](/h-0902/)、[pip install で error: externally-managed-environment が出たときの原因と直し方（Ubuntu 24.04）](/h-0903/)、[Pythonで FileNotFoundError: [Errno 2] No such file or directory が出たときの原因と直し方（相対パスと実行場所）](/h-0009/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/venv.html 、https://docs.npmjs.com/cli/v11/commands/npm-ls

## ステップ4：小さく再現する

原因の見当がついたら、新しい空のフォルダを作り、エラーに関係する部分だけを数行のコードに書き出して、同じエラーが出るかを試します。これを「最小の再現」と呼びます。元のプログラムでは何十個もの要素が絡み合っていても、数行で同じエラーが出れば、原因はその数行の中にあると絞り込めます。逆に、数行では出ないなら、削った部分のどこかに原因があると分かります。

このサイトの手順記事も、すべてこのやり方で作っています。使い捨てのフォルダの中だけで、エラーが出る状態をわざと作り、直し方を実行して、エラーが消えたことを実行ログで確かめています。たとえば循環インポートは2つの小さなファイルで、Node.js のモジュール形式のエラーは `package.json` と1つのファイルで再現できます。小さな再現があれば、人に質問するときにもそのまま見せられます。

- つまずきやすい所: 元のプロジェクトのフォルダで試し続けることです。設定ファイルや入っているパッケージの影響が残るので、まっさらなフォルダで試すと違いがはっきりします。
- このサイトの手順記事: [Pythonで ImportError: cannot import name from partially initialized module（循環インポート）が出たときの原因と直し方](/h-0010/)、[Node.jsで SyntaxError: Cannot use import statement outside a module が出たときの原因と直し方](/h-0905/)、[Node.jsで ReferenceError: require is not defined in ES module scope が出たときの原因と直し方](/h-0036/)
- 公式ドキュメント: https://docs.python.org/ja/3/tutorial/modules.html 、https://nodejs.org/api/esm.html

## ステップ5：公式情報で調べる

検索するときは、エラーの最後の行をそのまま使うのが基本ですが、自分のファイル名、フォルダのパス、変数名、列名のような「自分だけの部分」は外します。たとえば `KeyError: '売上'` なら、`pandas KeyError 列名` のように、ライブラリ名とエラーの種類を組み合わせると、同じ状況の情報に当たりやすくなります。日本語の文字コードのエラーなら、`UnicodeDecodeError cp932` のように、エラー文に出ている文字コードの名前を入れます。

検索で見つけた解決策は、書かれた時期と、使っているバージョンが自分の環境と合っているかを確かめてから試します。ライブラリの仕様はバージョンで変わるため、最終的な根拠は公式ドキュメントに置くのが安全です。npm の ERESOLVE のように、エラー文そのものに「どのパッケージ同士がぶつかっているか」が書かれている場合は、検索の前にその部分を読むと、調べる範囲を絞れます。

- つまずきやすい所: 検索で見つけたオプションを意味を調べずに付けることです。npm の `--force` のように、エラーを消す代わりに問題を先送りするだけのものもあります。
- このサイトの手順記事: [Pythonで UnicodeDecodeError: 'utf-8' codec can't decode byte が出たときの原因と直し方（日本語CSV）](/h-0901/)、[pandasで KeyError: '列名' が出たときの原因と直し方（列は存在するのに）](/h-0007/)、[npm install で ERESOLVE unable to resolve dependency tree が出たときの原因と直し方](/h-0033/)
- 公式ドキュメント: https://docs.python.org/ja/3/library/exceptions.html 、https://docs.npmjs.com/cli/v11/commands/npm-ls

## ステップ6：直ったことを確かめて記録する

直し方を見つけたら、エラーが出たときと同じ手順でもう一度実行し、エラーが出ないことと、期待した結果が出ることの両方を確かめます。エラーが消えただけで、値が空のまま処理が進んでいる、ということもあるからです。このサイトの記事に「直し方と実行ログ」を載せているのも、エラーが消えたあとの出力まで確かめるためです。

動く状態に戻ったら、Git で commit しておきます。次に何かを試して動かなくなっても、動いていた時点との違いを `git diff` で見比べたり、その時点に戻したりできます。直した内容と原因を commit のメッセージに一言書いておくと、同じエラーに再び出会ったときの手がかりになります。

- つまずきやすい所: 複数の直し方を同時に試して、どれが効いたのか分からなくなることです。1つ変えたら1回実行する、を繰り返します。
- このサイトの手順記事: [git pull で fatal: refusing to merge unrelated histories が出たときの原因と直し方](/h-0904/)、[npm install -g で EACCES: permission denied が出たときの原因と直し方](/h-0034/)
- 公式ドキュメント: https://git-scm.com/book/ja/v2

## 独学で進めるか、スクールを使うか

この6つのステップは、公式ドキュメントとこのサイトの手順記事を使えば、独学で身につけられるように並べています。エラーの種類ごとの直し方は、このサイトでも実行して確かめた記事を少しずつ増やしています。

一方で、ステップ4の小さな再現を作っても原因が分からないときや、自分のコードを人に見てもらいながら調べ方そのものを教わりたいときは、質問できる環境を持つのも1つの方法です。オンラインのプログラミングスクールには、質問を受け付けているところがあります。このサイトではスクールを受講して確かめてはいないため、ここではリンクの紹介にとどめます。学べる内容や質問の受け付け方、料金などの条件は、申し込む前に公式サイトで確認してください。

## まとめ

エラーを自力で解決するには、エラー文の最後の行を読み、原因の行と実行環境を確かめ、小さく再現してから公式情報で調べ、直ったことを再実行で確かめる、という順番で進めるのがおすすめです。どのステップも、このサイトの手順記事で実際の出力を見ながら練習できます。このページは、手順記事が増えるたびに表と本文を更新します。
