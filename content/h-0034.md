## 結論：グローバルの置き場所に書き込む権限がありません。置き場所を自分のホームの下に変えると解決します

`npm error code EACCES` と `permission denied` は、`npm install -g`（グローバルインストール）の置き場所が root（管理者）の持ち物で、いまのユーザーに書き込む権限がないときに出ます。この環境では、一般ユーザーで `npm install -g cowsay` を実行してこのエラーを再現し、npm の公式ドキュメントが案内している方法（グローバルの置き場所をホームの下のフォルダに変えて、PATH に足す）でインストールが通り、コマンドも動くことを確認しました。古い npm では、同じエラーが `npm ERR! code EACCES` と表示されます。

```text 実行ログ
$ mkdir -p ~/.npm-global

$ npm config set prefix ~/.npm-global

$ npm config get prefix
/tmp/run-h-0034/.npm-global

$ npm install -g cowsay

added 41 packages in 1s
```

## 検証環境

| 項目 | バージョン |

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。この記事では、ホームフォルダの場所が `/tmp/run-h-0034` になっています。お使いの環境では `/home/ユーザー名` などに読み替えてください。

## エラーの再現：一般ユーザーで npm install -g を実行する

エラー文は長いですが、読むところは次の2行です。

- `Error: EACCES: permission denied, mkdir '/opt/node22/lib/node_modules/cowsay'`：`/opt/node22/lib/node_modules` の中に cowsay のフォルダを作ろうとして（mkdir）、権限がないと断られています。
- `It is likely you do not have the permissions to access this file as the current user`：いまのユーザーには、このファイルを扱う権限がなさそうだ、という説明です。

`at async ...` で始まる行は npm の内部の場所を示しているだけなので、読み飛ばしてかまいません。途中の `npm notice` は npm の新しいバージョンのお知らせで、このエラーとは関係ありません。お使いの環境では、パスが `/usr/local/lib/node_modules` や `/usr/lib/node_modules` になっていることがあります。

## 原因：グローバルの置き場所（prefix）が root の持ち物になっている

`npm install -g` で入れたパッケージは、npm の設定 `prefix` が指すフォルダの下（`lib/node_modules`）に置かれます。いまの置き場所と、その持ち主を確かめました。

```text 実行ログ
$ npm config get prefix
/opt/node22

$ ls -ld /opt/node22/lib/node_modules
drwxr-xr-x 5 root root 4096 Nov 16 19:05 /opt/node22/lib/node_modules
```

置き場所は `/opt/node22` で、その下の `lib/node_modules` は持ち主が root、権限が `drwxr-xr-x` でした。この表示は「持ち主（root）だけが書き込めて、ほかのユーザーは読むことしかできない」という意味です。一般ユーザーの ubuntu には書き込む権限がないため、cowsay のフォルダを作れずにエラーになっていました。

エラー文の最後には「root として実行し直す」ことも書かれていますが、npm の公式ドキュメントは、このエラーへの対処として置き場所を変える方法か、Node のバージョン管理ツールで入れ直す方法を案内しています。この記事では、置き場所を変える方法を実行しました。

## 直し方：グローバルの置き場所をホームの下に変えて、PATH に足す

まず、ホームの下にグローバル用のフォルダ `.npm-global` を作り、`npm config set prefix` で置き場所をそこに変えます。この設定はホームの `.npmrc` に保存されるので、次からも有効です。

```text 実行ログ
$ mkdir -p ~/.npm-global

$ npm config set prefix ~/.npm-global

$ npm config get prefix
/tmp/run-h-0034/.npm-global

$ npm install -g cowsay

added 41 packages in 1s

3 packages are looking for funding
  run `npm fund` for details
```

置き場所がホームの下に変わり、同じ `npm install -g cowsay` がエラーにならずに終わりました。ただし、この時点ではまだコマンドが見つかりません。

```text 実行ログ
$ cowsay hello
bash: line 1: cowsay: command not found
```

コマンドの本体は `~/.npm-global/bin` に置かれますが、このフォルダがまだ PATH（コマンドを探す場所の一覧）に入っていないためです。`~/.bashrc` の最後に PATH を足す1行を書き、読み込み直しました。

```text 実行ログ
$ echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.bashrc

$ tail -n 1 ~/.bashrc
export PATH="$HOME/.npm-global/bin:$PATH"

$ source ~/.bashrc && which cowsay
/tmp/run-h-0034/.npm-global/bin/cowsay

$ source ~/.bashrc && cowsay hello
 _______
< hello >
 -------
        \   ^__^
         \  (oo)\_______
            (__)\       )\/\
                ||----w |
                ||     ||
```

`which cowsay` で `~/.npm-global/bin` の下のコマンドが見つかり、cowsay が動きました。最後に、グローバルに入っているパッケージを確かめました。

```text 実行ログ
$ npm ls -g
/tmp/run-h-0034/.npm-global/lib
`-- cowsay@1.6.0
```

グローバルの置き場所がホームの下の `.npm-global/lib` になり、cowsay 1.6.0 がそこに入っていることが分かります。新しく開いたターミナルでは `~/.bashrc` が自動で読み込まれるので、`source` を打たなくても使えます（bash の場合）。zsh を使っている場合は、`~/.zshrc` に同じ1行を書いてください。

## うまくいかないとき

- **グローバルに入れなくてよい場合**：そのプロジェクトの中だけで使うツールなら、`-g` を付けずにプロジェクトのフォルダで入れ、`npx` で動かす方法もあります。プロジェクトの中の `node_modules` に入るので、置き場所の権限は関係ありません。この環境で、prefix の設定とは別のフォルダで試したところ、エラーなく入り、`npx` で動きました。

```text 実行ログ
$ npm init -y > /dev/null && npm install cowsay

added 41 packages, and audited 42 packages in 960ms

3 packages are looking for funding
  run `npm fund` for details

found 0 vulnerabilities

$ npx cowsay local
 _______
< local >
 -------
        \   ^__^
         \  (oo)\_______
            (__)\       )\/\
                ||----w |
                ||     ||
```

- **置き場所を変えたのに command not found のまま**：PATH の1行を書いたファイルが、使っているシェルで読み込まれていない可能性があります。`echo $SHELL` でシェルを確かめ、そのシェルの設定ファイルに書いてから、ターミナルを開き直してください。
- **Node のバージョン管理ツールで入れ直す方法**：npm の公式ドキュメントでは、nvm などのバージョン管理ツールで Node.js を入れ直す方法がいちばんのおすすめとして案内されています。この記事では確かめていないため、手順は公式ドキュメント「Resolving EACCES permissions errors when installing packages globally」をご確認ください。Windows では置き場所の仕組みが違うため、同じ手順にはなりません。

## まとめ

`npm error code EACCES`（`permission denied`）は、`npm install -g` の置き場所（prefix）が root の持ち物で、一般ユーザーに書き込む権限がないときに出ていました。この環境では、`npm config set prefix ~/.npm-global` で置き場所をホームの下に変え、`~/.npm-global/bin` を PATH に足すことで、インストールが通り、コマンドも動きました。プロジェクトの中だけで使うツールなら、`-g` を付けずに入れて `npx` で動かす方法でも、権限のエラーは出ませんでした。
