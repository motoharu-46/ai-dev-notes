## 結論：2つのファイルがお互いをimportし合っているのが原因です。片方の依存をなくして「一方通行」にすると直ります

`ImportError: cannot import name 'Item' from partially initialized module 'shop.models' (most likely due to a circular import)` は、ファイルAがファイルBをimportし、ファイルBもファイルAをimportしている（循環インポート）ときに出ます。この環境では、Bの中でAを必要としていた関数を別のファイルに移し、importの向きをA→Bの一方通行にしたところ、エラーが消えて正しく動きました。直した後の `shop/utils.py` は、次のように `models` を import しない形です。

```python
def format_price(price):
    return f"{price:,}円"
```

## 検証環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 24.04.5 LTS |
| Python | Python 3.13.18 |

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

## エラーの再現：2つのファイルがお互いをimportしている

`shop` というパッケージ（フォルダ）に、商品を表すクラス `Item` を書いた `models.py` と、値段を「1,200円」の形にする関数などを書いた `utils.py` を置きました。`models.py` は値段の表示に `utils.py` の `format_price` を使い、`utils.py` はサンプルの商品を作るために `models.py` の `Item` を使っています。つまり、2つのファイルがお互いを import しています。

```text 実行ログ
$ ls shop
__init__.py
models.py
utils.py

$ cat shop/models.py
from shop.utils import format_price


class Item:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def label(self):
        return f"{self.name}: {format_price(self.price)}"

$ cat shop/utils.py
from shop.models import Item


def format_price(price):
    return f"{price:,}円"


def make_sample():
    return Item("ノート", 1200)

$ cat main.py
from shop.models import Item

item = Item("ペン", 150)
print(item.label())
```

`main.py` を実行すると、次のエラーになりました。

```text 実行ログ
$ python3 main.py
Traceback (most recent call last):
  File "/tmp/run-h-0010/main.py", line 1, in <module>
    from shop.models import Item
  File "/tmp/run-h-0010/shop/models.py", line 1, in <module>
    from shop.utils import format_price
  File "/tmp/run-h-0010/shop/utils.py", line 1, in <module>
    from shop.models import Item
ImportError: cannot import name 'Item' from partially initialized module 'shop.models' (most likely due to a circular import) (/tmp/run-h-0010/shop/models.py)
```

エラー文の読み方は次のとおりです。

- トレースバックは上から順に「main.py が models.py を読み込み → models.py が utils.py を読み込み → utils.py が models.py を読み込もうとした」という流れを表しています。ファイル名が1周して元に戻っているのが、循環インポートの目印です。
- `partially initialized module 'shop.models'` は「shop.models はまだ読み込みの途中（初期化が終わっていない）」という意味です。
- `most likely due to a circular import` は、Python自身が「おそらく循環インポートが原因」と教えてくれている部分です。

## 原因：読み込み途中のモジュールからは名前を取り出せない

Pythonはファイルを import するとき、ファイルの先頭から1行ずつ実行していき、最後まで実行し終わって初めて、その中のクラスや関数が使える状態になります。

今回の流れでは、`models.py` の1行目（`from shop.utils import format_price`）を実行した時点で `utils.py` の読み込みに移ります。`utils.py` の1行目で `models.py` から `Item` を取り出そうとしますが、`models.py` はまだ1行目で止まっていて、`class Item` の行まで進んでいません。そのため「読み込み途中の shop.models には Item という名前がない」というエラーになります。

どちらのファイルから読み込み始めるかで、エラーに出てくる名前も変わります。`utils.py` から先に import すると、今度は `format_price` が見つからないというエラーになりました。

```text 実行ログ
$ python3 -c "import shop.utils" 2>&1 | tail -n 1
ImportError: cannot import name 'format_price' from partially initialized module 'shop.utils' (most likely due to a circular import) (/tmp/run-h-0010/shop/utils.py)
```

エラーに出る名前は違っても、原因は同じ「2つのファイルがお互いを必要としていること」です。片方のファイルの名前を直しても解決しないので、importの関係そのものを見直します。

## 直し方：importを一方通行にする

`utils.py` が `models.py` を必要としていたのは、`make_sample` 関数の1か所だけでした。そこで `make_sample` を新しいファイル `shop/samples.py` に移し、`utils.py` からは `models.py` の import を消しました。これで「models → utils」「samples → models」という一方通行になり、ぐるっと1周する経路がなくなります。

```text 実行ログ
$ cat shop/utils.py
def format_price(price):
    return f"{price:,}円"

$ cat shop/samples.py
from shop.models import Item


def make_sample():
    return Item("ノート", 1200)
```

この状態で実行すると、エラーが消えて値段つきの表示が出ました。移した `make_sample` も、`utils.py` 単体の import も問題なく動きました。

```text 実行ログ
$ python3 main.py
ペン: 150円

$ python3 -c "from shop.samples import make_sample; print(make_sample().label())"
ノート: 1,200円

$ python3 -c "import shop.utils; print(shop.utils.format_price(98000))"
98,000円
```

一般に、`utils.py` のような「どこからでも使われる小さな部品」のファイルは、ほかの自作ファイルを import しない形にしておくと、循環インポートが起きにくくなります。

## うまくいかないとき

- **ファイルを分けられない場合**は、import を関数の中に移す方法もあります。関数の中の import は、その関数が呼ばれたときに実行されるため、ファイルを読み込む時点では循環が起きません。元の `utils.py` の `make_sample` の中に import を移したところ、こちらでも動きました。ただし、どのファイルが何に依存しているかが見えにくくなるので、まずは上の「一方通行にする」方法をおすすめします。

```text 実行ログ
$ cd alt && cat shop/utils.py
def format_price(price):
    return f"{price:,}円"


def make_sample():
    from shop.models import Item

    return Item("ノート", 1200)

$ cd alt && python3 main.py
ペン: 150円

$ cd alt && python3 -c "from shop.utils import make_sample; print(make_sample().label())"
ノート: 1,200円
```

- 自分で作ったファイルの名前が、標準ライブラリやインストールしたライブラリと同じ（例: `random.py`、`csv.py`）場合も、`partially initialized module` を含む似たエラーになることがあります。この場合は自分のファイル名を変えてください（この記事では確認していません）。モジュールがどこから探されるかは、公式チュートリアルの「モジュール検索パス」をご確認ください。
- import がどういう順番で実行されるかの詳しい仕組みは、公式ドキュメントの「インポートシステム」に説明があります。

## まとめ

`ImportError: cannot import name ... from partially initialized module (most likely due to a circular import)` は、2つのファイルがお互いを import していて、片方が読み込み途中のまま名前を取り出そうとしたときに出ていました。この環境では、片方にだけ必要だった関数を別のファイルに移して import を一方通行にすると、エラーが消えて正しく動きました。
