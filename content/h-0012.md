## 結論：読み込もうとした文字列がJSONではない（空、またはHTML）のが原因です。中身を確かめてからJSONとして読むと解決します

`JSONDecodeError: Expecting value: line 1 column 1 (char 0)` は、「1行目の1文字目に、JSONの値が来るはずなのに来なかった」という意味です。つまり、渡した文字列が最初の1文字からJSONになっていません。この環境では、よくある2つの場面「JSONファイルが空だった」「APIのつもりで受け取った中身が404エラーのHTMLだった」の両方でこのエラーを再現し、ファイルに正しいJSONを書く、受け取った中身のステータスとContent-Typeを確かめてから読む、という直し方でエラーが消えることを確認しました。

```python
if "application/json" not in content_type:
    print(f"JSONではありません（Content-Type: {content_type}）")
    print(text[:100])
    raise SystemExit(1)

data = json.loads(text)
```

## 検証環境

| 項目 | バージョン |
|---|---|
| OS | Ubuntu 24.04.5 LTS |
| Python | Python 3.13.18 |

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

## エラーの再現1：設定ファイル（config.json）を読み込むとエラーになる

設定を `config.json` に置いて、`json.load()` で読み込むだけのスクリプトです。

```text 実行ログ
$ cat load_config.py
import json

with open("config.json", encoding="utf-8") as f:
    config = json.load(f)

print(config["name"])
```

エラー文の読み方は次のとおりです。

- トレースバックのうち、自分で書いたファイルは一番上の `load_config.py`, `line 4` だけです。その下の `json/__init__.py` や `json/decoder.py` はPython本体の中なので、そこを直す必要はありません。
- 最後の行の `Expecting value` は「値（`{`、`[`、数字、文字列など）が来るはずだった」、`line 1 column 1 (char 0)` は「その場所が1行目の1文字目（先頭から0文字目）だった」という意味です。先頭からつまずいているので、中身がまるごとJSONになっていないと考えられます。

## 原因1：ファイルが空（0バイト）だった

上の `ls -l` の結果にあるとおり、`config.json` のサイズは0でした。文字数を数えても0です。空の文字列はJSONとして正しくないため、先頭の1文字目で `Expecting value` になります。保存し忘れたファイルや、書き込みの途中で止まったファイルで起きやすい形です。

```text 実行ログ
$ wc -c config.json
0 config.json
```

## 直し方1：ファイルに正しいJSONを書く

`config.json` にJSONを書き込んでから、同じスクリプトをもう一度実行しました。今度はエラーにならず、`name` の値が表示されました。

```text 実行ログ
$ cat config.json
{"name": "山田"}

$ python3 load_config.py
山田
```

## エラーの再現2：APIの応答をjson.loadsするとエラーになる

次は、Web APIから受け取った文字列をJSONとして読む場面です。外部のサイトには接続せず、同じパソコンの中（127.0.0.1）にテスト用のサーバーを立てました。`/api/user` にだけJSONを返し、それ以外のURLには404のHTMLを返します。

```text 実行ログ
$ cat server.py
from http.server import BaseHTTPRequestHandler, HTTPServer


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/api/user":
            body = '{"name": "山田", "age": 30}'.encode("utf-8")
            self.send_response(200)
            self.send_header("Content-Type", "application/json; charset=utf-8")
        else:
            body = b"<!DOCTYPE html><html><body><h1>404 Not Found</h1></body></html>"
            self.send_response(404)
            self.send_header("Content-Type", "text/html")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass


HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

このサーバーに対して、受け取った文字列をそのまま `json.loads()` に渡すクライアントを動かしました。URLは `/api/user` のつもりで、`/api/users` と1文字多く書いてしまっています。

```text 実行ログ

import json
import urllib.error
import urllib.request

url = "http://127.0.0.1:8000/api/users"
try:
    with urllib.request.urlopen(url) as resp:
        text = resp.read().decode("utf-8")
except urllib.error.HTTPError as e:
    text = e.read().decode("utf-8")

data = json.loads(text)
print(data["name"])
```

ファイルのときと同じ `Expecting value: line 1 column 1 (char 0)` になりました。

## 原因2：受け取った中身がJSONではなく404エラーのHTMLだった

何を受け取っていたのかを確かめるため、ステータスコード、Content-Type、本文の先頭60文字を表示するスクリプトを動かしました。

```text 実行ログ
$ cat debug.py
import urllib.error
import urllib.request

url = "http://127.0.0.1:8000/api/users"
try:
    resp = urllib.request.urlopen(url)
except urllib.error.HTTPError as e:
    resp = e

print("status:", resp.status)
print("Content-Type:", resp.headers.get("Content-Type"))
print("body:", repr(resp.read().decode("utf-8")[:60]))

$ python3 debug.py
status: 404
Content-Type: text/html
body: '<!DOCTYPE html><html><body><h1>404 Not Found</h1></body></ht'
```

ステータスは404、Content-Typeは `text/html` で、本文は `<!DOCTYPE html>` から始まるHTMLでした。JSONの先頭に `<` は来られないため、1文字目で `Expecting value` になったことが分かります。URLの打ち間違いのほか、サーバー側のエラーページやログイン画面が返ってきたときも同じ形になります。エラーが出たら、まず `print(repr(text[:100]))` のように中身の先頭を表示すると、原因の見当がつきます。

## 直し方2：ステータスとContent-Typeを確かめてから読む

URLを正しい `/api/user` に直したうえで、HTTPエラーのときと、Content-TypeがJSONでないときは `json.loads()` を呼ばずに、分かりやすいメッセージを出して止めるようにしました。

```text 実行ログ
$ cat client_fixed.py
import json
import sys
import urllib.error
import urllib.request

url = sys.argv[1] if len(sys.argv) > 1 else "http://127.0.0.1:8000/api/user"
try:
    with urllib.request.urlopen(url) as resp:
        content_type = resp.headers.get("Content-Type", "")
        text = resp.read().decode("utf-8")
except urllib.error.HTTPError as e:
    print(f"HTTPエラー {e.code}: {url}")
    raise SystemExit(1)

if "application/json" not in content_type:
    print(f"JSONではありません（Content-Type: {content_type}）")
    print(text[:100])
    raise SystemExit(1)

data = json.loads(text)
print(data["name"])
```

正しいURLではJSONを読めて名前が表示され、間違ったURLを渡したときは `JSONDecodeError` ではなく「HTTPエラー 404」と、何が起きたのかが分かるメッセージで止まりました。

```text 実行ログ
$ python3 client_fixed.py
山田

$ python3 client_fixed.py http://127.0.0.1:8000/api/users
HTTPエラー 404: http://127.0.0.1:8000/api/users
```

## うまくいかないとき

- **json.loads() にファイル名を渡していないか**確認してください。`json.loads()` は「JSONの文字列」を受け取る関数なので、`json.loads("config.json")` と書くと、`config.json` という文字そのものをJSONとして読もうとして、同じエラーになりました。ファイルから読むときは、`open()` で開いて `json.load()`（末尾に s がない方）に渡すと直りました。

```text 実行ログ
$ cd alt && cat wrong_loads.py
import json

data = json.loads("config.json")
print(data)

$ cd alt && python3 wrong_loads.py 2>&1 | tail -n 1
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

```text 実行ログ
$ cd alt && cat right_load.py
import json

with open("config.json", encoding="utf-8") as f:
    data = json.load(f)
print(data)

$ cd alt && python3 right_load.py
{'name': '鈴木'}
```

- **エラー文の場所が line 1 column 1 以外**（例: `line 3 column 5`）のときは、先頭はJSONとして読めていて、途中に書き方の誤りがあります。表示された行と列の付近を見直してください。JSONの書き方の決まりは、公式ドキュメントの json モジュールのページで確認できます。

## まとめ

`JSONDecodeError: Expecting value: line 1 column 1 (char 0)` は、読み込もうとした中身が先頭からJSONになっていないときに出ていました。この環境では、空のファイル、404エラーのHTML、ファイル名をそのまま `json.loads()` に渡した場合の3つで再現し、正しいJSONを書く、ステータスとContent-Typeを確かめてから読む、`json.load()` でファイルを読む、という直し方でそれぞれエラーが消えました。
