pandasで SettingWithCopyWarning が出たときの原因と消し方（.copy() と .loc）【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-11　更新日 2026-11-11　手順・エラー解決 / Python

この記事の手順は 2026年11月11日 に下記の環境で実際に実行して確認しました。

結論：絞り込んだ表に代入しているのが原因です。.copy() するか .loc で1回で代入すると消えます

SettingWithCopyWarning は、df[条件] で絞り込んだ結果に、あとから列を足したり値を入れたりしたときに pandas 2.x が出す警告です。絞り込んだ結果を別の表として使いたいなら df[条件].copy() で明示的にコピーし、元の表の値を書き換えたいなら df.loc[条件, "列名"] = 値 の形で1回で代入します。この環境では、どちらの書き方でも警告が出なくなり、意図どおりの結果になりました。

high = df[df["金額"] >= 100].copy()
df.loc[df["金額"] >= 100, "金額"] = 0

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
PythonPython 3.13.18
pandaspandas 2.3.3（比較用に pandas 3.1.1）

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。この警告は pandas 2.x までのもので、pandas 3.0 以降では出ません（後半で pandas 3.1.1 の結果も載せています）。

エラーの再現：絞り込んだ表に列を足すと警告が出る

商品と金額だけの小さなCSVを用意し、金額が100円以上の行だけを取り出して、税込の金額の列を足すプログラムを書きました。pandas を学び始めたころによく書く形です。

実行ログ
$ cat sales.csv
商品,金額
りんご,120
バナナ,80
メロン,980

$ cat warn.py
import pandas as pd

df = pd.read_csv("sales.csv")
high = df[df["金額"] >= 100]
high["税込"] = high["金額"] * 1.1
print(high)

pandas 2.3.3 で実行すると、結果は表示されるものの、その前に次の警告が出ました。

実行ログ
$ python warn.py
/tmp/run-h-0008/warn.py:5: SettingWithCopyWarning: 
A value is trying to be set on a copy of a slice from a DataFrame.
Try using .loc[row_indexer,col_indexer] = value instead

See the caveats in the documentation: https://pandas.pydata.org/pandas-docs/stable/user_guide/indexing.html#returning-a-view-versus-a-copy
  high["税込"] = high["金額"] * 1.1
    商品   金額      税込
0  りんご  120   132.0
2  メロン  980  1078.0

1行目の warn.py:5 が、警告の原因になった行（5行目の high["税込"] = ...）です。2行目は「DataFrameから切り出したもの（のコピー）に値を入れようとしています」という意味です。エラーではなく警告なので、プログラムは最後まで動いています。

原因：元の表の一部なのか、コピーなのかがはっきりしない

df[df["金額"] >= 100] の結果は、元の df とつながった「一部分」なのか、切り離された「コピー」なのかが、pandas 2.x では場合によって変わります。そのため、そこに代入したときに「元の表も変わってほしいのか」「変わらなくてよいのか」を pandas が判断できず、念のため警告を出しています。

本当に困るのは、元の表を書き換えるつもりで書いたのに、書き換わっていない場合です。次のように、絞り込みと列の指定を [ ] で2回続けて書くと（連鎖代入と呼ばれます）、同じ警告が出たうえで、元の表は変わっていませんでした。

実行ログ
$ cat chain.py
import pandas as pd

df = pd.read_csv("sales.csv")
df[df["金額"] >= 100]["金額"] = 0
print(df)

$ python chain.py
/tmp/run-h-0008/chain.py:4: SettingWithCopyWarning: 
A value is trying to be set on a copy of a slice from a DataFrame.
Try using .loc[row_indexer,col_indexer] = value instead

See the caveats in the documentation: https://pandas.pydata.org/pandas-docs/stable/user_guide/indexing.html#returning-a-view-versus-a-copy
  df[df["金額"] >= 100]["金額"] = 0
    商品   金額
0  りんご  120
1  バナナ   80
2  メロン  980

100円以上の金額を0にしたつもりでも、りんごは120、メロンは980のままです。値が入ったのは途中で作られたコピーのほうで、そのコピーはすぐに捨てられています。この警告は、こうした「書き換えたつもりで書き換わっていない」ミスを知らせるためのものです。

直し方：やりたいことに合わせて書き分ける

絞り込んだ表を別の表として使うなら .copy()

warn.py のように、元の表は変えずに、取り出した行だけで計算したい場合は、絞り込んだ直後に .copy() を付けます。「これは元の表とは別物です」とはっきりさせる書き方です。

実行ログ
$ cat fix_copy.py
import pandas as pd

df = pd.read_csv("sales.csv")
high = df[df["金額"] >= 100].copy()
high["税込"] = high["金額"] * 1.1
print(high)

$ python fix_copy.py
    商品   金額      税込
0  りんご  120   132.0
2  メロン  980  1078.0

警告が消え、結果は同じでした。

元の表を書き換えるなら .loc で1回で代入

chain.py のように元の表の値を変えたい場合は、[ ] を2回続けずに、.loc[行の条件, "列名"] の形で行と列を一度に指定して代入します。

実行ログ
$ cat fix_loc.py
import pandas as pd

df = pd.read_csv("sales.csv")
df.loc[df["金額"] >= 100, "金額"] = 0
print(df)

$ python fix_loc.py
    商品  金額
0  りんご   0
1  バナナ  80
2  メロン   0

警告が出なくなり、100円以上だったりんごとメロンの金額が0に書き換わりました。

うまくいかないとき

  • 警告を表示しない設定もありますが、おすすめしません。 pd.options.mode.chained_assignment = None を書くと、この環境でも警告は出なくなりました。ただし、次のとおり元の表が書き換わっていない問題はそのまま残ります。警告が出ないぶん、ミスに気づきにくくなります。
実行ログ
$ cat hide.py
import pandas as pd

pd.options.mode.chained_assignment = None
df = pd.read_csv("sales.csv")
df[df["金額"] >= 100]["金額"] = 0
print(df)

$ python hide.py
    商品   金額
0  りんご  120
1  バナナ   80
2  メロン  980
  • pandas 3.0 以降では、この警告は出ません。 pandas 3.0 から Copy-on-Write という仕組みが標準になり、絞り込んだ結果は常に元の表とは別物として扱われます。同じ warn.py を pandas 3.1.1 で実行すると、警告なしで動きました。一方、chain.py の連鎖代入は ChainedAssignmentError という別の警告になり、やはり元の表は変わりませんでした。.loc で1回で代入する fix_loc.py は、pandas 3.1.1 でも同じ結果でした。
実行ログ
$ python -c "import pandas; print(pandas.__version__)"
3.1.1

$ python warn.py
    商品   金額      税込
0  りんご  120   132.0
2  メロン  980  1078.0

$ python chain.py
/tmp/run-h-0008/chain.py:4: ChainedAssignmentError: A value is being set on a copy of a DataFrame or Series through chained assignment.
Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).

Try using '.loc[row_indexer, col_indexer] = value' instead, to perform the assignment in a single step.

See the documentation for a more detailed explanation: https://pandas.pydata.org/docs/dev/user_guide/migration.html#chained-assignment
  df[df["金額"] >= 100]["金額"] = 0
    商品   金額
0  りんご  120
1  バナナ   80
2  メロン  980

$ python fix_loc.py
    商品  金額
0  りんご   0
1  バナナ  80
2  メロン   0

どのバージョンでも、「別の表にするなら .copy()、元の表を変えるなら .loc で1回で代入」と書いておけば、同じように動きます。

  • 自分の pandas のバージョンは python -c "import pandas; print(pandas.__version__)" で確かめられます。pandas が見つからないエラーになる場合は、Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv） をご覧ください。

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。

まとめ

SettingWithCopyWarning は、pandas 2.x で df[条件] の結果に代入したときに、「元の表が変わるかどうか分からない」ことを知らせる警告です。この環境では、取り出した行を別の表として使うなら .copy()、元の表を書き換えるなら .loc[条件, "列名"] = 値 と書くことで、警告が消えて意図どおりの結果になりました。

この手順の次に読む記事

  • pandasで KeyError: '列名' が出たときの原因と直し方（列は存在するのに）
  • Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv）
