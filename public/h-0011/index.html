Pythonで RecursionError: maximum recursion depth exceeded が出たときの原因と直し方【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-16　更新日 2026-11-16　手順・エラー解決 / Python

この記事の手順は 2026年11月16日 に下記の環境で実際に実行して確認しました。

結論：関数が自分自身を呼ぶ回数が上限（既定1000回）を超えたのが原因です。ループに書き換えるか、止まる条件を直すと解決します

RecursionError: maximum recursion depth exceeded は、関数が自分自身を呼び出す「再帰」が深くなりすぎて、Pythonの上限（この環境では1000）を超えたときに出ます。原因は「止まる条件はあるが、入力が大きくて深くなりすぎた」か「止まる条件に一度も当てはまらず、無限に呼び続けている」かのどちらかです。この環境では、前者はループに書き換えて、後者は止まる条件を直して、どちらもエラーが消えることを確認しました。ループに書き換えた関数は次のとおりです。

def total(n):
    """1からnまでの合計をループで求める"""
    result = 0
    for i in range(1, n + 1):
        result += i
    return result

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
PythonPython 3.13.18

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：小さい数では動くのに、大きい数で止まる

1からnまでの合計を、再帰で求める関数を書きました。n が0になったら0を返し、それ以外は「n ＋ 1からn-1までの合計」を返す、という形です。止まる条件（if n == 0）はきちんと書いてあります。

実行ログ
$ cat calc.py
def total(n):
    """1からnまでの合計を再帰で求める"""
    if n == 0:
        return 0
    return n + total(n - 1)


print(total(100))
print(total(5000))

実行すると、total(100) は 5050 と正しく表示されましたが、total(5000) で次のエラーになりました。

実行ログ
$ python3 calc.py
5050
Traceback (most recent call last):
  File "/tmp/run-h-0011/calc.py", line 9, in <module>
    print(total(5000))
          ~~~~~^^^^^^
  File "/tmp/run-h-0011/calc.py", line 5, in total
    return n + total(n - 1)
               ~~~~~^^^^^^^
  File "/tmp/run-h-0011/calc.py", line 5, in total
    return n + total(n - 1)
               ~~~~~^^^^^^^
  File "/tmp/run-h-0011/calc.py", line 5, in total
    return n + total(n - 1)
               ~~~~~^^^^^^^
  [Previous line repeated 996 more times]
RecursionError: maximum recursion depth exceeded

エラー文の読み方は次のとおりです。

  • 同じ line 5, in total が何度も並んでいるのは、total が total を呼び、その中でまた total を呼び……と重なっていった跡です。
  • [Previous line repeated 996 more times] は「同じ行がさらに996回続いたので省略した」という意味です。トレースバックに並んだ数と合わせて、およそ1000回の呼び出しで止まったことが分かります。
  • 最後の maximum recursion depth exceeded が「再帰の深さの上限を超えた」という本文です。

原因：再帰の深さには上限がある

Pythonは、関数の呼び出しが終わらないまま次々と重なっていくと、ある深さで処理を止めて RecursionError を出します。上限は sys.getrecursionlimit() で確認できます。この環境では1000でした。

実行ログ
$ python3 -c "import sys; print(sys.getrecursionlimit())"
1000

total(5000) は、n が0になるまで約5000回 total を呼び続ける必要があります。止まる条件は正しいのに、そこに着く前に上限の1000を超えてしまったのが原因です。total(100) が動いたのは、100回なら上限に届かないためです。

直し方：再帰をループに書き換える

再帰の深さが入力の大きさに比例して増える処理は、for ループに書き換えると、上限を気にせずに済みます。合計を入れる変数 result を用意して、1からnまで順に足していく形にしました。

実行ログ
$ cat calc_loop.py
def total(n):
    """1からnまでの合計をループで求める"""
    result = 0
    for i in range(1, n + 1):
        result += i
    return result


print(total(100))
print(total(5000))
print(total(1_000_000))

実行すると、エラーが出ずに3つとも計算できました。再帰の版では止まった5000だけでなく、100万でも問題なく動きました。

実行ログ
$ python3 calc_loop.py
5050
12502500
500000500000

うまくいかないとき

  • 止まる条件に一度も当てはまらない場合も、同じエラーになります。次の countdown は2ずつ減らしていますが、奇数から始めると n == 0 を飛び越えて -1、-3…と進み、最後は RecursionError になりました。条件を n <= 0 にすると、正しく止まりました。小さな入力でもすぐにこのエラーが出るときは、上限ではなく止まる条件を疑ってください。
実行ログ
$ cd alt && python3 countdown.py 2>&1 | head -n 4
5
3
1
-1

$ cd alt && python3 countdown.py 2>&1 | tail -n 1
RecursionError: maximum recursion depth exceeded
実行ログ
$ cd alt && cat countdown_fixed.py
def countdown(n):
    if n <= 0:
        print("発射！")
        return
    print(n)
    countdown(n - 2)


countdown(5)

$ cd alt && python3 countdown_fixed.py
5
3
1
発射！
  • 再帰を書いたつもりがない場合は、クラスの @property を疑ってください。セッター（@name.setter）の中で self.name = ... と書くと、そのセッター自身がまた呼ばれて、無限に繰り返します。値を入れる先を self._name のように別の名前にすると直りました。
実行ログ
$ cd alt && python3 user.py 2>&1 | tail -n 5
  File "/tmp/run-h-0011/alt/user.py", line 11, in name
    self.name = value.strip()
    ^^^^^^^^^
  [Previous line repeated 995 more times]
RecursionError: maximum recursion depth exceeded
実行ログ
$ cd alt && cat user_fixed.py
class User:
    def __init__(self, name):
        self.name = name

    @property
    def name(self):
        return self._name

    @name.setter
    def name(self, value):
        self._name = value.strip()


u = User(" 山田 ")
print(u.name)

$ cd alt && python3 user_fixed.py
山田
  • 上限を引き上げる方法 sys.setrecursionlimit() もあります。上限を10000にしたところ、再帰の版でも total(5000) が計算できました。ただし公式ドキュメントには、上限を高くしすぎるとPython自体がクラッシュすることがあると書かれています。入力がどこまで大きくなるか分からない処理では、まずループへの書き換えを検討してください。
実行ログ
$ cd alt && python3 calc_limit.py
10000
12502500

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。

まとめ

RecursionError: maximum recursion depth exceeded は、再帰の呼び出しが上限（この環境では1000）を超えたときに出ていました。入力が大きくて深くなる場合はループに書き換え、小さな入力でも出る場合は止まる条件やプロパティのセッターを見直すと、この環境ではどちらもエラーが消えました。
