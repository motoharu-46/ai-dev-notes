JavaScriptで SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON が出たときの原因と直し方（fetch）【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-25　更新日 2026-11-25　手順・エラー解決 / JavaScript

この記事の手順は 2026年11月25日 に下記の環境で実際に実行して確認しました。

結論：JSONのつもりで受け取った応答が、実はHTML（エラーページなど）です。URLを直し、res.json() の前に応答を確かめると直ります

`SyntaxError: Unexpected token '<', "` で始まる404ページを返したときによく起きます。
直し方は、まず curl -i などで実際の応答（ステータスと Content-Type）を確かめ、URLの間違いを直すことです。あわせて res.ok と Content-Type を確認してから res.json() を呼ぶようにしておくと、同じことが起きても原因がすぐ分かります。
この環境では、URLを正しく直すとJSONが読めるようになり、確認つきの書き方ではエラーの代わりに「404 text/html」と分かるメッセージが出ることを確認しました。

実行ログ
$ node client.js
[ { id: 1, name: 'Sato' }, { id: 2, name: 'Suzuki' } ]

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Node.jsNode.js v22.23.5
curlcurl 8.5.0

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。ブラウザで同じことが起きた場合も、エラー文の表現が少し違うだけで、原因と直し方は同じです。

エラーの再現：JSONを返すAPIのURLを1文字間違える

外部のサイトには通信せず、手元（localhost）にJSONを返す小さなサーバーを作って再現しました。/api/users にアクセスするとユーザーの一覧をJSONで返し、それ以外のURLには、よくあるWebサーバーと同じようにHTMLの404ページを返します。

実行ログ
$ cat server.js
const http = require("http");

const users = [
  { id: 1, name: "Sato" },
  { id: 2, name: "Suzuki" },
];

const server = http.createServer((req, res) => {
  if (req.url === "/api/users") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify(users));
    return;
  }
  res.writeHead(404, { "Content-Type": "text/html; charset=utf-8" });
  res.end("<!DOCTYPE html>\n<html><body><h1>404 Not Found</h1></body></html>\n");
});

server.listen(3000, () => {
  console.log("Server running at http://localhost:3000/");
});

$ node server.js > server.log 2>&1 &

$ cat server.log
Server running at http://localhost:3000/

このサーバーに、fetch でアクセスしてJSONを読むコードを書きます。ここでは、正しくは /api/users のところを /api/user（s が抜けている）と書いてしまった状態です。

実行ログ
$ cat client.js
async function main() {
  const res = await fetch("http://localhost:3000/api/user");
  const users = await res.json();
  console.log(users);
}

main();

実行すると、次のエラーになりました。

実行ログ
$ node client.js
<anonymous_script>:1
<!DOCTYPE html>
^

SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON
    at JSON.parse (<anonymous>)
    at parseJSONFromBytes (node:internal/deps/undici/undici:5959:19)
    at successSteps (node:internal/deps/undici/undici:5940:27)
    at fullyReadBody (node:internal/deps/undici/undici:4832:9)
    at process.processTicksAndRejections (node:internal/process/task_queues:103:5)
    at async consumeBody (node:internal/deps/undici/undici:5949:7)
    at async main (/tmp/run-h-0039/app/client.js:3:17)

エラー文の要点は2か所です。Unexpected token '<' は「JSONとしてありえない文字 < が出てきた」という意味で、続く "<!DOCTYPE "... は、受け取った中身の先頭がそうなっていたことを示しています。最後の行の client.js:3:17 は、3行目の res.json() で起きたことを示しています。つまり fetch 自体は成功していて、受け取った中身がJSONではなかった、ということです。

原因：サーバーがJSONではなくHTMLの404ページを返している

fetch は、サーバーが404（ページが見つからない）を返しても、それだけではエラーにしません。返ってきた中身をそのまま渡すので、HTMLの404ページを res.json() で読もうとして失敗します。

実際に何が返っているかは、curl -i で応答の見出し（ヘッダー）ごと表示すると確かめられます。間違ったURLと正しいURLの両方を見てみました。

実行ログ
$ curl -s -i http://localhost:3000/api/user
HTTP/1.1 404 Not Found
Content-Type: text/html; charset=utf-8
Date: Tue, 24 Nov 2026 21:49:19 GMT
Connection: keep-alive
Keep-Alive: timeout=5
Transfer-Encoding: chunked

<!DOCTYPE html>
<html><body><h1>404 Not Found</h1></body></html>
実行ログ
$ curl -s -i http://localhost:3000/api/users
HTTP/1.1 200 OK
Content-Type: application/json
Date: Tue, 24 Nov 2026 21:49:19 GMT
Connection: keep-alive
Keep-Alive: timeout=5
Transfer-Encoding: chunked

[{"id":1,"name":"Sato"},{"id":2,"name":"Suzuki"}]

間違ったURLでは 404 Not Found と Content-Type: text/html が返り、中身は ` で始まっています。これがエラー文に出ていた "<!DOCTYPE "... の正体です。正しいURLでは 200 OK と Content-Type: application/json` が返り、中身はJSONでした。

なお、curl の表示にある Date: は、サーバーが応答した日時をイギリス時間（GMT）で表したものです。

直し方1：URLの間違いを直す

原因はURLの s 抜けなので、/api/user を /api/users に直します。

実行ログ
$ sed -i 's#/api/user"#/api/users"#' client.js

$ cat client.js
async function main() {
  const res = await fetch("http://localhost:3000/api/users");
  const users = await res.json();
  console.log(users);
}

main();

$ node client.js
[ { id: 1, name: 'Sato' }, { id: 2, name: 'Suzuki' } ]

エラーが消え、ユーザーの一覧が表示されました。

直し方2：res.json() の前に応答を確かめる

URLを直せばこのエラーは消えますが、サーバーの不具合やログイン切れなど、ほかの理由でHTMLが返ってくることもあります。そのたびに分かりにくい SyntaxError が出ないように、res.ok（ステータスが200番台なら true）と Content-Type を確かめてから res.json() を呼ぶ関数にしました。JSONでないときは、res.text() で中身の先頭を読んでメッセージに入れます。

実行ログ
$ cat client-fixed.js
async function getJson(url) {
  const res = await fetch(url);
  const type = res.headers.get("content-type") || "";
  if (!res.ok || !type.includes("application/json")) {
    const body = await res.text();
    throw new Error(`JSONではない応答です: ${res.status} ${type}\n${body.slice(0, 80)}`);
  }
  return res.json();
}

async function main() {
  try {
    const users = await getJson("http://localhost:3000/api/user");
    console.log(users);
  } catch (err) {
    console.error(err.message);
  }

  const users = await getJson("http://localhost:3000/api/users");
  console.log(users);
}

main();

間違ったURLと正しいURLの両方で実行しました。

実行ログ
$ node client-fixed.js
JSONではない応答です: 404 text/html; charset=utf-8
<!DOCTYPE html>
<html><body><h1>404 Not Found</h1></body></html>

[ { id: 1, name: 'Sato' }, { id: 2, name: 'Suzuki' } ]

間違ったURLでは、SyntaxError の代わりに「404」「text/html」と、何が返ってきたかが分かるメッセージが出ました。正しいURLでは、これまでどおりJSONが読めています。

うまくいかないとき

  • URLは正しいのに同じエラーが出る場合は、まず curl -i で同じURLを開き、ステータスと Content-Type を確かめてください。この記事の再現のように、HTMLが返っていれば、サーバー側がJSONを返していないことが分かります。
  • ブラウザで起きている場合は、開発者ツールの「ネットワーク」タブで、そのリクエストのステータスと応答の中身を見ると同じことが確かめられます。この記事ではブラウザでは実行していないため、画面の見方はお使いのブラウザの公式ドキュメントをご確認ください。
  • エラー文が Unexpected token '<' 以外の場合（JSONの別の場所で失敗している場合など）は、この記事では確かめていません。直し方2のように res.text() で中身を表示すると、何が返っているかは確認できます。res.json() や res.ok の詳しい動きは、MDN の「Response: json() メソッド」「Response: ok プロパティ」をご確認ください。

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。

まとめ

SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON は、res.json() で読んだ中身がJSONではなくHTMLだったときに出るエラーです。この環境では、URLの s 抜けでサーバーがHTMLの404ページを返していたのが原因で、URLを直すとJSONが読めるようになりました。res.ok と Content-Type を確かめてから res.json() を呼ぶようにすると、同じことが起きても何が返ってきたかがすぐ分かることも確認しました。
