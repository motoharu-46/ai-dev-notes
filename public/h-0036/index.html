Node.jsで ReferenceError: require is not defined in ES module scope が出たときの原因と直し方【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-20　更新日 2026-11-20　手順・エラー解決 / JavaScript

この記事の手順は 2026年11月20日 に下記の環境で実際に実行して確認しました。

結論：ES モジュールとして読まれたファイルでは require が使えません。import に書き換えると直ります

Node.jsで ReferenceError: require is not defined in ES module scope が出たら、そのファイルは package.json の "type": "module" によって ES モジュールとして読まれています。
直し方は、require(...) を import 文に書き換えることです。JSON ファイルは import config from "./config.json" with { type: "json" }; の形で読み込めます。
この環境では、書き換えた後に同じファイルがエラーなく動くことを確認しました。

実行ログ
$ cat index.js
import fs from "node:fs";
import config from "./config.json" with { type: "json" };

const files = fs.readdirSync(".");
console.log(`${config.appName}（ポート ${config.port}）`);
console.log(`ファイル数: ${files.length}`);

$ node index.js
メモ帳（ポート 3000）
ファイル数: 3

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Node.jsNode.js v22.23.5
npmnpm 10.9.9

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：type が module のプロジェクトで require を使う

ネットの記事やサンプルからコピーした require のコードを、"type": "module" が書かれたプロジェクトで動かそうとしたときによく起きます。別の記事の手順で import を使えるように package.json を変えた後、古いファイルで出ることもあります。

ここでは npm init -y で package.json を作り、"type" を "module" にしました。

実行ログ
$ npm init -y > /dev/null && npm pkg set type=module && npm pkg get type
"module"

設定ファイル config.json を読み込んで表示するだけの index.js を用意しました。require で標準モジュールの fs と JSON ファイルを読み込む、よくある書き方です。

実行ログ
$ cat config.json
{
  "appName": "メモ帳",
  "port": 3000
}

$ cat index.js
const fs = require("node:fs");
const config = require("./config.json");

const files = fs.readdirSync(".");
console.log(`${config.appName}（ポート ${config.port}）`);
console.log(`ファイル数: ${files.length}`);

実行すると、次のエラーになりました。

実行ログ
$ node index.js
file:///tmp/run-h-0036/app/index.js:1
const fs = require("node:fs");
           ^

ReferenceError: require is not defined in ES module scope, you can use import instead
This file is being treated as an ES module because it has a '.js' file extension and '/tmp/run-h-0036/app/package.json' contains "type": "module". To treat it as a CommonJS script, rename it to use the '.cjs' file extension.
    at file:///tmp/run-h-0036/app/index.js:1:12
    at ModuleJob.run (node:internal/modules/esm/module_job:343:25)
    at async onImport.tracePromise.__proto__ (node:internal/modules/esm/loader:681:26)
    at async asyncRunEntryPointWithESMLoader (node:internal/modules/run_main:117:5)

Node.js v22.23.5

要点は ReferenceError: の行とその次の行です。1行目は「ES モジュールの中には require が定義されていない。代わりに import を使える」という意味です。2行目には、なぜ ES モジュールとして読まれたのか（拡張子が .js で、package.json に "type": "module" があるから）と、もう1つの直し方（拡張子を .cjs にする）が書かれています。^ の位置は、1行目の require を指しています。

原因：require は CommonJS の書き方で、ES モジュールにはない

Node.js には、ファイルの書き方（モジュールの方式）が2種類あります。require と module.exports を使う CommonJS と、import と export を使う ES モジュールです。

Node.js の公式ドキュメント「Modules: Packages」によると、.js ファイルをどちらの方式で読むかは、一番近い package.json の "type" で決まります。"module" なら ES モジュールとして読みます。そして公式ドキュメント「Modules: ECMAScript modules」には、ES モジュールでは require・exports・module.exports が使えないと書かれています。

つまり、コードの書き方は CommonJS なのに、ファイルは ES モジュールとして読まれているという食い違いが原因です。コードの中身が間違っているわけではありません。

直し方：require を import に書き換える

プロジェクトが "type": "module" で、これからも import を使っていくなら、ファイルの書き方を ES モジュールにそろえます。今回のファイルでは、2行だけ書き換えました。

  • const fs = require("node:fs"); → import fs from "node:fs";
  • const config = require("./config.json"); → import config from "./config.json" with { type: "json" };

JSON ファイルを import するときは、with { type: "json" } を付けます。付けないと JSON として読み込めません（公式ドキュメント「Modules: ECMAScript modules」の JSON modules の項）。書き換えたファイルを実行しました。

実行ログ
$ cat index.js
import fs from "node:fs";
import config from "./config.json" with { type: "json" };

const files = fs.readdirSync(".");
console.log(`${config.appName}（ポート ${config.port}）`);
console.log(`ファイル数: ${files.length}`);

$ node index.js
メモ帳（ポート 3000）
ファイル数: 3

エラーが消え、config.json の中身が表示されました。

うまくいかないとき

  • ファイルを書き換えたくない場合は、拡張子を .cjs にします。 エラー文の2行目に書かれていた方法です。拡張子が .cjs のファイルは、package.json の "type" に関係なく CommonJS として読まれます。この環境では、元の require のコードを index.cjs という名前でコピーして実行すると、そのまま動きました。
実行ログ
$ cp index.js index.cjs && node index.cjs
メモ帳（ポート 3000）
ファイル数: 4

（ファイル数が4なのは、コピーした index.cjs の分が増えているためです。）

  • ES モジュールのまま、一部だけ require を使いたい場合は createRequire を使います。 node:module の createRequire で require 関数を作ると、ES モジュールの中でも require で読み込めました。
実行ログ
$ cat index2.js
import { createRequire } from "node:module";

const require = createRequire(import.meta.url);
const config = require("./config.json");

console.log(`${config.appName}（ポート ${config.port}）`);

$ node index2.js
メモ帳（ポート 3000）
  • プロジェクト全体が require で書かれていて、import を使う予定がないなら、package.json の "type": "module" を外す（または "commonjs" にする）方法もあります。ただし、その場合は import を使っているファイルで逆のエラーが出ます。その直し方は「Node.jsで SyntaxError: Cannot use import statement outside a module が出たときの原因と直し方」で確認しています。
  • require を import に書き換えた後、__dirname is not defined in ES module scope のように別の名前で同じ種類のエラーが出ることがあります。この記事では実行して確かめていません。ES モジュールでの代わりの書き方は、Node.js 公式ドキュメント「Modules: ECMAScript modules」の「No require, exports, or module.exports」と import.meta の項をご確認ください。

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。

まとめ

ReferenceError: require is not defined in ES module scope は、package.json の "type": "module" によって ES モジュールとして読まれているファイルで require を使ったときのエラーです。この環境では、require を import に書き換える（JSON は with { type: "json" } を付ける）とエラーが消えました。書き換えたくない場合は、拡張子を .cjs にするか、createRequire を使う方法でも動くことを確認しました。
