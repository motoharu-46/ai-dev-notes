pip install で error: externally-managed-environment が出たときの原因と直し方（Ubuntu 24.04）【実行して確認】

公開日 2026-11-07　更新日 2026-11-07　手順・エラー解決 / Python

※本記事はアフィリエイト広告（PR）を含みます。

この記事の手順は 2026年11月6日 に下記の環境で実際に実行して確認しました。

結論：OSが管理するPythonには直接入れられません。venvを作ってそこに入れます

Ubuntu 24.04 の標準のPythonで pip install を実行すると、error: externally-managed-environment が出てインストールが止まります。OSが使うPythonをpipで壊さないための仕組み（PEP 668）によるもので、故障ではありません。この環境では、仮想環境（venv）を作ってその中にインストールしたところ、問題なく入りました。

実行ログ
$ python3.12 -m venv .venv

$ .venv/bin/python -m pip install rich 2>&1 | grep Successfully
Successfully installed markdown-it-py-4.2.0 mdurl-0.1.2 pygments-2.21.0 rich-15.0.0

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
PythonPython 3.12.3（Ubuntu標準）
pippip 24.0

この検証環境には複数のPythonが入っているため、Ubuntu標準のPythonを python3.12 と明示して実行しています。Ubuntu 24.04 だけを使っている場合、python3 や pip と打つと同じPython 3.12.3が動きます。お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：Ubuntu標準のPythonに pip install する

Ubuntu標準のPythonとpipのバージョンです。

実行ログ
$ python3.12 --version
Python 3.12.3

$ python3.12 -m pip --version
pip 24.0 from /usr/lib/python3/dist-packages/pip (python 3.12)

このPythonに、表示を見やすくするライブラリ rich をインストールしようとしました。

実行ログ
$ python3.12 -m pip install rich
error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install
    python3-xyz, where xyz is the package you are trying to
    install.
    
    If you wish to install a non-Debian-packaged Python package,
    create a virtual environment using python3 -m venv path/to/venv.
    Then use path/to/venv/bin/python and path/to/venv/bin/pip. Make
    sure you have python3-full installed.
    
    If you wish to install a non-Debian packaged Python application,
    it may be easiest to use pipx install xyz, which will manage a
    virtual environment for you. Make sure you have pipx installed.
    
    See /usr/share/doc/python3.12/README.venv for more information.

note: If you believe this is a mistake, please contact your Python installation or OS distribution provider. You can override this, at the risk of breaking your Python installation or OS, by passing --break-system-packages.
hint: See PEP 668 for the detailed specification.

エラー文には、3つの道が書かれています。apt でOSのパッケージとして入れる、仮想環境を作ってそこに入れる、アプリなら pipx を使う、の3つです。

原因：PEP 668の目印ファイルがある

PEP 668 は、OSが管理しているPythonに、pipが勝手にパッケージを入れないようにする決まりです。Pythonの標準ライブラリの置き場所に EXTERNALLY-MANAGED というファイルがあると、pipはこのエラーを出して止まります。この環境でも、そのファイルがありました。

実行ログ
$ ls /usr/lib/python3.12/EXTERNALLY-MANAGED
/usr/lib/python3.12/EXTERNALLY-MANAGED

OSの部品にはPythonで動くものがあり、pipで同じライブラリの別のバージョンを上書きすると、OS側の部品が動かなくなるおそれがあります。それを防ぐための仕組みです。

直し方：仮想環境（venv）を作って、その中に入れる

作業用のフォルダで仮想環境 .venv を作り、仮想環境のPythonでインストールしました。

実行ログ
$ python3.12 -m venv .venv

$ .venv/bin/python -m pip install rich 2>&1 | grep Successfully
Successfully installed markdown-it-py-4.2.0 mdurl-0.1.2 pygments-2.21.0 rich-15.0.0

入ったことを、仮想環境のPythonでバージョンを表示して確かめました。

実行ログ
$ .venv/bin/python -c "import rich; from importlib.metadata import version; print(version(\"rich\"))"
15.0.0

以後このライブラリを使うときは、.venv/bin/python で実行するか、source .venv/bin/activate で仮想環境を有効にしてから python を使います。

うまくいかないとき

  • 仮想環境を作るコマンドがエラーになる場合は、上のエラー文の案内どおり、Ubuntuのパッケージ python3-full が入っているかをご確認ください。この検証環境では最初から仮想環境を作れたため、この場合は実行して確かめていません。
  • エラー文の最後にある --break-system-packages を付けると、インストール自体は通ります。ただし、エラー文にあるとおりPythonやOSを壊すおそれがあるため、この記事では勧めません。
  • 仮想環境にインストールしたのに ModuleNotFoundError が出る場合は、「ModuleNotFoundError: No module named が出たときの直し方（venv）」をご覧ください。

まとめ

error: externally-managed-environment は、OSが管理するPythonを守るためのエラーです。python3 -m venv .venv で仮想環境を作り、.venv/bin/python -m pip install でその中に入れると、この環境では問題なくインストールできました。
