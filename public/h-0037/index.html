JavaScriptで TypeError: Cannot read properties of undefined (reading 'xxx') が出たときの原因と直し方【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-21　更新日 2026-11-21　手順・エラー解決 / JavaScript

この記事の手順は 2026年11月21日 に下記の環境で実際に実行して確認しました。

結論：undefined の値からプロパティを読もうとしています。読む前に値があるかを確かめると直ります

TypeError: Cannot read properties of undefined (reading 'city') は、「.city を読もうとした相手が undefined だった」というエラーです。reading の後ろの名前は読もうとしたプロパティで、問題なのはその1つ手前の値です。
直し方は、手前の値が無い場合を考えて書くことです。オプショナルチェーン ?. と ?? を使うと、user.address?.city ?? "（住所なし）" のように1行で書けます。
この環境では、書き換えた後にエラーが消え、住所のないデータも最後まで表示されることを確認しました。

実行ログ
$ cat index.js
const users = require("./users.json");

for (const user of users) {
  console.log(`${user.name}: ${user.address?.city ?? "（住所なし）"}`);
}

$ node index.js
佐藤: 東京
鈴木: （住所なし）
高橋: 大阪

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Node.jsNode.js v22.23.5

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。ブラウザ（Chrome など）でも同じ文のエラーになります。

エラーの再現：一部のデータにだけ項目がない

APIの応答やJSONファイルなど、外から来たデータを順番に表示するときによく起きます。ほとんどのデータには項目があるのに、一部のデータだけ項目が欠けていると、そこで止まります。

ここでは、3人分のユーザーデータ users.json を用意しました。2人目の「鈴木」にだけ address がありません。これを読み込んで、名前と住所の市区町村を表示する index.js を書きました。

実行ログ
$ cat users.json
[
  { "name": "佐藤", "address": { "city": "東京" } },
  { "name": "鈴木" },
  { "name": "高橋", "address": { "city": "大阪" } }
]

$ cat index.js
const users = require("./users.json");

for (const user of users) {
  console.log(`${user.name}: ${user.address.city}`);
}

実行すると、1人目は表示されたあと、次のエラーで止まりました。

実行ログ
$ node index.js
佐藤: 東京
/tmp/run-h-0037/app/index.js:4
  console.log(`${user.name}: ${user.address.city}`);
                                            ^

TypeError: Cannot read properties of undefined (reading 'city')
    at Object.<anonymous> (/tmp/run-h-0037/app/index.js:4:45)
    at Module._compile (node:internal/modules/cjs/loader:1781:14)
    at Object..js (node:internal/modules/cjs/loader:1913:10)
    at Module.load (node:internal/modules/cjs/loader:1505:32)
    at Function._load (node:internal/modules/cjs/loader:1309:12)
    at wrapModuleLoad (node:internal/modules/cjs/loader:254:19)
    at Function.executeUserEntryPoint [as runMain] (node:internal/modules/run_main:171:5)
    at node:internal/main/run_main_module:36:49

Node.js v22.23.5

エラー文の読み方は次のとおりです。

  • 1行目の index.js:4 は、エラーが起きたファイルと行番号です。その下にその行のコードが表示され、^ が問題の位置（.city の直前）を指しています。
  • TypeError: Cannot read properties of undefined (reading 'city') が本体です。「undefined のプロパティは読めない（読もうとしたのは city）」という意味です。
  • `at Object. (...index.js:4:45) の数字は「4行目の45文字目」です。その下の node:internal/...` の行は Node.js 内部の呼び出しなので、読まなくてかまいません。

ここで勘違いしやすいのは、city が無いのではない点です。city を読もうとした相手、つまり user.address が undefined になっています。

原因：手前の値（user.address）が undefined になっている

本当に user.address が undefined なのかを確かめるため、2人目のデータとその address を表示しました。

実行ログ
$ node -e "const users = require(\"./users.json\"); console.log(users[1]); console.log(users[1].address);"
{ name: '鈴木' }
undefined

2人目のデータには name しかなく、address を読むと undefined になりました。JavaScriptでは、オブジェクトにないプロパティを読んでもエラーにはならず、undefined が返ります。ところが、その undefined からさらに .city を読もうとすると、MDN の「TypeError: "x" has no properties」の解説にあるとおり、TypeError になります。

まとめると、a.b.c の形で c を読むときにこのエラーが出たら、a.b が undefined です。エラーの reading に出ている名前の1つ手前を調べてください。

直し方：?. と ?? で、値が無い場合を書いておく

住所が無いデータもあり得るなら、それを前提に書きます。オプショナルチェーン ?. は、手前の値が undefined（または null）のときに、エラーにせず undefined を返す書き方です。さらに ??（Null 合体演算子）を付けると、undefined のときに代わりの値を出せます。4行目だけ書き換えました。

  • user.address.city → user.address?.city ?? "（住所なし）"

書き換えたファイルを実行しました。

実行ログ
$ cat index.js
const users = require("./users.json");

for (const user of users) {
  console.log(`${user.name}: ${user.address?.city ?? "（住所なし）"}`);
}

$ node index.js
佐藤: 東京
鈴木: （住所なし）
高橋: 大阪

エラーが消え、住所のない「鈴木」も含めて3人とも表示されました。

なお、?. を付ける場所は「undefined になり得る値」の直後です。今回は user.address が無いことがあるので address?. としました。全部の . に付けると、本来あるはずのデータが欠けていても気づけなくなるので、必要なところだけに付けるのがおすすめです。

うまくいかないとき

  • 配列の範囲の外を読んでいることもあります。 for 文の条件を <= にすると、最後に1つ多く回って、存在しない要素（undefined）を読みます。この環境で、i <= users.length と書いたファイルを実行すると、3人表示したあとに (reading 'name') のエラーになりました。
実行ログ
$ cat loop.js
const users = require("./users.json");

for (let i = 0; i <= users.length; i++) {
  console.log(users[i].name);
}

$ node loop.js
佐藤
鈴木
高橋
/tmp/run-h-0037/app/loop.js:4
  console.log(users[i].name);
                       ^

TypeError: Cannot read properties of undefined (reading 'name')
    at Object.<anonymous> (/tmp/run-h-0037/app/loop.js:4:24)
    at Module._compile (node:internal/modules/cjs/loader:1781:14)
    at Object..js (node:internal/modules/cjs/loader:1913:10)
    at Module.load (node:internal/modules/cjs/loader:1505:32)
    at Function._load (node:internal/modules/cjs/loader:1309:12)
    at wrapModuleLoad (node:internal/modules/cjs/loader:254:19)
    at Function.executeUserEntryPoint [as runMain] (node:internal/modules/run_main:171:5)
    at node:internal/main/run_main_module:36:49

Node.js v22.23.5

配列の番号は0から始まるので、要素が3つなら最後の番号は2です。条件を i < users.length に直すと、エラーなく3人表示されました。

実行ログ
$ cat loop.js
const users = require("./users.json");

for (let i = 0; i < users.length; i++) {
  console.log(users[i].name);
}

$ node loop.js
佐藤
鈴木
高橋
  • エラー文が Cannot read properties of null の場合も、考え方は同じです（読もうとした相手が null）。ブラウザで document.querySelector() の結果に対して起きることが多いですが、この記事ではブラウザでは実行して確かめていません。?. の動きは MDN の「オプショナルチェーン (?.)」をご確認ください。
  • fetch などで取ったデータで起きる場合は、受け取ったデータの形が思っていたものと違うことが多いです。まず console.log() でデータ全体を表示し、どの階層が undefined なのかを確かめてください。

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。
