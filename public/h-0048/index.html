git push で ! [rejected] main -> main (non-fast-forward) が出たときの原因と直し方【実行して確認】

公開日 2026-11-26　更新日 2026-11-26　手順・エラー解決 / Git・開発環境

この記事の手順は 2026年11月26日 に下記の環境で実際に実行して確認しました。

結論：リモートに自分の持っていないコミットがあるためです。pull で取り込んでから push し直すと直ります

! [rejected] main -> main (non-fast-forward) は、「リモートの main には、手元にないコミットが先に積まれているので、このまま上書きはしません」という意味のエラーです。別のパソコンや別の人が先に push したときによく起きます。
直し方は、git pull --no-rebase origin main（マージ）か git pull --rebase origin main（リベース）でリモートの変更を取り込み、もう一度 git push origin main することです。
この環境では、どちらの方法でも push が通り、リモートと手元の両方の変更が残ることを確認しました。

実行ログ
$ git pull --no-rebase origin main
From /tmp/run-h-0048/work/remote
 * branch            main       -> FETCH_HEAD
Merge made by the 'ort' strategy.
 office.py | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 office.py

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Gitgit version 2.43.0

GitHub の代わりに、同じパソコンの中に作ったリモート用のリポジトリ（remote.git）を使っています。「会社のパソコン（pc-office）」と「家のパソコン（myapp）」の2つの作業場所から、同じリモートに push する状況を作りました。お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：別の場所から先に push されたあとで push する

まず、家のパソコン側でリモートを clone しました。この時点のコミットは1つです。

実行ログ
$ git clone remote.git myapp
Cloning into 'myapp'...
done.

$ git log --oneline
0053981 Initial commit

次に、会社のパソコン側で office.py を追加して、先に push しました。

実行ログ
$ echo 'print("office")' > office.py && git add office.py && git commit -q -m "add office.py" && git push origin main
To /tmp/run-h-0048/work/remote.git
   0053981..dc1dbd2  main -> main

家のパソコン側では、そのことを知らないまま app.py を追加してコミットし、push しました。

実行ログ
$ echo 'print("home")' > app.py && git add app.py && git commit -q -m "add app.py" && git log --oneline
3b08aa6 add app.py
0053981 Initial commit

$ git push origin main
To /tmp/run-h-0048/work/remote.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to '/tmp/run-h-0048/work/remote.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. This is usually caused by another repository pushing to
hint: the same ref. If you want to integrate the remote changes, use
hint: 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.

最初は (fetch first) と出ました。手元がリモートの新しいコミットをまだ一度も取ってきていないときの表示です。git fetch でリモートの状態だけを取ってきてから push し直すと、今回のエラー (non-fast-forward) になりました。

実行ログ
$ git fetch origin
From /tmp/run-h-0048/work/remote
   0053981..dc1dbd2  main       -> origin/main

$ git push origin main
To /tmp/run-h-0048/work/remote.git
 ! [rejected]        main -> main (non-fast-forward)
error: failed to push some refs to '/tmp/run-h-0048/work/remote.git'
hint: Updates were rejected because the tip of your current branch is behind
hint: its remote counterpart. If you want to integrate the remote changes,
hint: use 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.

要点は hint: の1行目と3行目です。「手元のブランチの先端が、リモートより遅れている」「取り込みたいなら、push の前に git pull を使う」と書かれています。(fetch first) と (non-fast-forward) は表示が違うだけで、原因と直し方は同じです。

原因：手元とリモートの履歴が分かれている

git status と git log --graph --all で状態を確かめました。

実行ログ
$ git status
On branch main
Your branch and 'origin/main' have diverged,
and have 1 and 1 different commits each, respectively.
  (use "git pull" if you want to integrate the remote branch with yours)

nothing to commit, working tree clean

$ git log --oneline --graph --all
* 3b08aa6 add app.py
| * dc1dbd2 add office.py
|/  
* 0053981 Initial commit

Initial commit のあとで、手元には add app.py、リモートには add office.py と、別々のコミットが積まれて枝分かれしています。push は、リモートのブランチを「今の先端の続き」に進める（fast-forward）ときだけ、そのまま受け付けます。このまま手元の main で上書きすると、リモートにある add office.py が消えてしまうため、Git が拒否しています。Git の公式ドキュメント（git-push の「NOTE ABOUT FAST-FORWARDS」）でも、この場合は先にリモートの変更を取り込むように説明されています。

直し方：git pull で取り込んでから push する

マージで取り込む --no-rebase を付けて pull しました。

実行ログ
$ git pull --no-rebase origin main
From /tmp/run-h-0048/work/remote
 * branch            main       -> FETCH_HEAD
Merge made by the 'ort' strategy.
 office.py | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 office.py

$ git log --oneline --graph
*   01e4dec Merge branch 'main' of /tmp/run-h-0048/work/remote
|\  
| * dc1dbd2 add office.py
* | 3b08aa6 add app.py
|/  
* 0053981 Initial commit

2つの枝がマージコミットでつながり、手元がリモートの先端を含む状態になりました。もう一度 push すると、今度は通りました。

実行ログ
$ git push origin main
To /tmp/run-h-0048/work/remote.git
   dc1dbd2..01e4dec  main -> main

$ ls
README.md
app.py
office.py

会社のパソコンで追加した office.py と、家のパソコンで追加した app.py の両方が残っています。

うまくいかないとき

  • マージコミットを作らずに履歴を1本にしたい場合は、--rebase で取り込めます。同じ状況をもう一度作って実行したところ、手元のコミットがリモートの先端の後ろに付け直され、push が通りました。
実行ログ
$ git pull --rebase origin main 2>&1 | tr '\r' '\n' | grep Successfully
Successfully rebased and updated refs/heads/main.

$ git log --oneline --graph
* 02f32a0 add app2.py
* f3ea136 add office2.py
*   01e4dec Merge branch 'main' of /tmp/run-h-0048/work/remote
|\  
| * dc1dbd2 add office.py
* | 3b08aa6 add app.py
|/  
* 0053981 Initial commit

$ git push origin main
To /tmp/run-h-0048/work/remote.git
   f3ea136..02f32a0  main -> main
  • 手元とリモートで同じファイルの同じ行を変えていると、pull のときに衝突（コンフリクト）します。この記事の検証ではファイルが重ならなかったため、衝突の解消は実行して確かめていません。手順は Git の公式ドキュメント（git-merge の「HOW TO RESOLVE CONFLICTS」）をご確認ください。
  • オプションを付けずに git pull だけを実行すると、fatal: Need to specify how to reconcile divergent branches. で止まることがあります。これは「マージかリベースかを選んでください」という案内なので、この記事のように --no-rebase か --rebase を付けてください。
  • エラーを消すために git push --force で上書きする方法も見かけますが、リモートにある他の人（または別のパソコン）のコミットが消えます。この記事では実行していません。使う場合の注意は公式ドキュメント（git-push の --force と --force-with-lease）をご確認ください。
  • 手元とリモートに共通のコミットが1つもないときは、pull が fatal: refusing to merge unrelated histories で止まります。その場合は git pull で fatal: refusing to merge unrelated histories が出たときの原因と直し方 をご覧ください。

まとめ

! [rejected] main -> main (non-fast-forward) や (fetch first) は、リモートに手元にないコミットがあり、そのまま push するとそれが消えてしまうために出るエラーです。この環境では、git pull --no-rebase origin main（または --rebase）でリモートの変更を取り込んでから git push origin main すると、両方の変更を残したまま push できました。
