npm install で ERESOLVE unable to resolve dependency tree が出たときの原因と直し方【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-18　更新日 2026-11-18　手順・エラー解決 / JavaScript

この記事の手順は 2026年11月18日 に下記の環境で実際に実行して確認しました。

結論：パッケージ同士が求めるバージョンが食い違っています。相手が求めるバージョンにそろえると解決します

npm error code ERESOLVE と unable to resolve dependency tree は、「あるパッケージが一緒に使う相手（peer dependency）として求めるバージョン」と、実際に入れようとしているバージョンが合わないときに出ます。この環境では、react 18 と react-dom 17 を同時に入れようとしてこのエラーを再現し、react-dom を react と同じ 18 系にそろえることでインストールが通り、プログラムも動くことを確認しました。古い npm（バージョン 6〜9 ごろ）では、同じエラーが npm ERR! code ERESOLVE と表示されます。

実行ログ
$ npm install react-dom@^18.3.1

added 5 packages, and audited 6 packages in 637ms

found 0 vulnerabilities

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Node.jsNode.js v22.23.5
npmnpm 10.9.9

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：react だけ 18 に上げたプロジェクトで npm install する

React のプロジェクトで、react だけを新しいバージョンに書き換え、react-dom を古いままにした、という場面を想定しました。package.json は次のとおりです。

実行ログ
$ cat package.json
{
  "name": "myapp",
  "version": "1.0.0",
  "private": true,
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^17.0.2"
  }
}

この状態で npm install を実行すると、次のエラーになりました。

実行ログ
$ npm install
npm error code ERESOLVE
npm error ERESOLVE unable to resolve dependency tree
npm error
npm error While resolving: myapp@1.0.0
npm error Found: react@18.3.1
npm error node_modules/react
npm error   react@"^18.3.1" from the root project
npm error
npm error Could not resolve dependency:
npm error peer react@"17.0.2" from react-dom@17.0.2
npm error node_modules/react-dom
npm error   react-dom@"^17.0.2" from the root project
npm error
npm error Fix the upstream dependency conflict, or retry
npm error this command with --force or --legacy-peer-deps
npm error to accept an incorrect (and potentially broken) dependency resolution.
npm error
npm error
npm error For a full report see:
npm error /tmp/run-h-0033/.npm/_logs/2026-11-17T21_49_03_058Z-eresolve-report.txt
npm error A complete log of this run can be found in: /tmp/run-h-0033/.npm/_logs/2026-11-17T21_49_03_058Z-debug-0.log

$ ls
package.json

エラーのあとに ls を実行すると package.json しかなく、node_modules は作られていませんでした。npm は食い違いを見つけた時点で、何もインストールせずに止まっています。

エラー文は長いですが、読むところは2か所です。

  • Found: react@18.3.1：プロジェクトに入ろうとしている react は 18.3.1 です。
  • Could not resolve dependency: の次の行 peer react@"17.0.2" from react-dom@17.0.2：react-dom 17.0.2 は「一緒に使う react は 17.0.2 でなければならない」と求めています。

つまり「react は 18 なのに、react-dom は react 17 を求めている」という食い違いです。自分のプロジェクトでエラーが出たときも、Found: の行と peer ... from ... の行を見比べると、どのパッケージ同士がぶつかっているかが分かります。

原因：react-dom 17 が react 17 を相手に指定している（peerDependencies）

パッケージは、自分と一緒に使う相手のパッケージとそのバージョンを peerDependencies として package.json に書いています。npm 7 以降は、この指定に合わないとインストールを止めるようになりました。それぞれのバージョンが何を求めているかは、npm view で確かめられます。

実行ログ
$ npm view react-dom@17.0.2 peerDependencies
{ react: '17.0.2' }

$ npm view react-dom@18.3.1 peerDependencies
{ react: '^18.3.1' }

react-dom 17.0.2 は react 17.0.2 だけ、react-dom 18.3.1 は react 18.3.1 以上の 18 系を求めていることが分かりました。react 18 と一緒に使えるのは react-dom 18 系です。

直し方：react-dom を react と同じ 18 系にそろえる

求められているバージョンに合わせて、react-dom を 18 系で入れ直しました。npm install パッケージ名@バージョン で入れると、package.json の指定も自動で書き換わります。

実行ログ
$ npm install react-dom@^18.3.1

added 5 packages, and audited 6 packages in 637ms

found 0 vulnerabilities

$ cat package.json
{
  "name": "myapp",
  "version": "1.0.0",
  "private": true,
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1"
  }
}

エラーにならずにインストールが終わり、package.json の react-dom が ^18.3.1 に変わりました。入ったバージョンの組み合わせは npm ls で確かめられます。

実行ログ
$ npm ls react react-dom
myapp@1.0.0 /tmp/run-h-0033/myapp
├─┬ react-dom@18.3.1
│ └── react@18.3.1 deduped
└── react@18.3.1

react-dom 18.3.1 が react 18.3.1 を使っていて、invalid などの警告はありません。最後に、react と react-dom を読み込んで HTML を1行作るだけの小さなプログラムを動かし、実際に使えることを確認しました。

実行ログ
$ cat index.js
const React = require("react");
const { renderToString } = require("react-dom/server");

const html = renderToString(React.createElement("h1", null, "Hello"));
console.log(html);
console.log("react:", React.version);

$ node index.js
<h1>Hello</h1>
react: 18.3.1

うまくいかないとき

  • エラー文が勧める --legacy-peer-deps について：エラー文には「--force か --legacy-peer-deps を付けて再実行すれば通る」と書かれています。同じ package.json（react 18・react-dom 17）で npm install --legacy-peer-deps を実行したところ、インストール自体は終わりました。ただし、そのあと npm ls で確かめると、react に invalid の印が付き、npm error code ELSPROBLEMS が出ました。食い違いが直ったわけではなく、チェックを外して入れただけです。エラー文にもあるとおり、壊れた組み合わせになることがあるため、まずはバージョンをそろえる方法を試してください。
実行ログ
$ npm install --legacy-peer-deps

added 6 packages, and audited 7 packages in 564ms

found 0 vulnerabilities

$ npm ls react react-dom
alt@1.0.0 /tmp/run-h-0033/alt
├─┬ react-dom@17.0.2
│ └── react@18.3.1 deduped invalid: "17.0.2" from node_modules/react-dom
└── react@18.3.1 invalid: "17.0.2" from node_modules/react-dom

npm error code ELSPROBLEMS
npm error invalid: react@18.3.1 /tmp/run-h-0033/alt/node_modules/react
  • ぶつかっている相手が react 以外のとき：考え方は同じです。エラー文の peer ○○@"バージョン" from △△@バージョン から、△△ が求める ○○ のバージョンを読み取り、npm view △△ peerDependencies で新しいバージョンの △△ が何を求めているかを確かめて、どちらかにそろえてください。この環境で確かめたのは react と react-dom の組み合わせだけです。オプションの詳しい意味は、公式ドキュメントの npm install のページで確認できます。

独学で行き詰まったときに、講座で体系的に学び直したい場合は、オンラインのプログラミングスクールもあります。

まとめ

npm error code ERESOLVE（unable to resolve dependency tree）は、パッケージが求める相手のバージョン（peerDependencies）と、実際に入れようとしたバージョンが食い違っているときに出ていました。この環境では、react 18 と react-dom 17 の組み合わせで再現し、エラー文の Found: と peer ... from ... の行から食い違いを読み取って、react-dom を 18 系にそろえることでインストールが通り、プログラムも動きました。
