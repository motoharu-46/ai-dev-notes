git pull で fatal: refusing to merge unrelated histories が出たときの原因と直し方【実行して確認】

公開日 2026-11-07　更新日 2026-11-07　手順・エラー解決 / Git・開発環境

この記事の手順は 2026年11月6日 に下記の環境で実際に実行して確認しました。

結論：共通の祖先がない2つの履歴を、Gitが自動では合わせないためです

手元で作ったリポジトリを、READMEつきで作ったGitHubのリポジトリにつなぐと、git pull で fatal: refusing to merge unrelated histories が出ることがあります。手元とGitHubの履歴に共通のコミットがないため、Gitが合わせるのを止めています。この環境では、--allow-unrelated-histories を付けて pull したところ、2つの履歴がマージされました。

実行ログ
$ git pull --no-rebase origin main --allow-unrelated-histories
From ../remote
 * branch            main       -> FETCH_HEAD
Merge made by the 'ort' strategy.
 README.md | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Gitgit version 2.43.0

GitHubの代わりに、同じパソコンの中に作ったリモート用のリポジトリ（../remote.git）を使っています。中身は「READMEを追加」して作ったGitHubのリポジトリと同じで、Initial commit というコミットが1つだけあります。お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：手元で作ったリポジトリを、別に作ったリモートにつなぐ

手元で新しくリポジトリを作り、最初のコミットをしました。

実行ログ
$ mkdir myapp && cd myapp && git init -q && echo "print(\"hello\")" > app.py && git add app.py && git commit -q -m "first commit" && git log --oneline
cb5c153 first commit

リモートを登録して pull すると、まず次のメッセージで止まりました。

実行ログ
$ git remote add origin ../remote.git

$ git pull origin main
From ../remote
 * branch            main       -> FETCH_HEAD
 * [new branch]      main       -> origin/main
hint: You have divergent branches and need to specify how to reconcile them.
hint: You can do so by running one of the following commands sometime before
hint: your next pull:
hint: 
hint:   git config pull.rebase false  # merge
hint:   git config pull.rebase true   # rebase
hint:   git config pull.ff only       # fast-forward only
hint: 
hint: You can replace "git config" with "git config --global" to set a default
hint: preference for all repositories. You can also pass --rebase, --no-rebase,
hint: or --ff-only on the command line to override the configured default per
hint: invocation.
fatal: Need to specify how to reconcile divergent branches.

これは「手元とリモートの履歴が分かれているので、マージかリベースかを選んでください」という案内です。マージを選ぶ --no-rebase を付けてもう一度 pull すると、今回のエラーが出ました。

実行ログ
$ git pull --no-rebase origin main
From ../remote
 * branch            main       -> FETCH_HEAD
fatal: refusing to merge unrelated histories

原因：2つの履歴に共通のコミットがない

ふつうのマージは、2つのブランチが分かれる前の共通のコミットを起点に、変更を合わせます。今回は、手元の first commit とリモートの Initial commit がそれぞれ別に作られたため、共通の起点がありません。Gitの公式ドキュメントでは、このような関係のない履歴のマージは既定で拒否され、--allow-unrelated-histories を付けたときだけ許可されると説明されています。別のプロジェクトを間違って混ぜてしまう事故を防ぐためです。

直し方：--allow-unrelated-histories を付けて pull する

つなぎたいリモートが正しいことを確かめてから、--allow-unrelated-histories を付けて pull しました。

実行ログ
$ git pull --no-rebase origin main --allow-unrelated-histories
From ../remote
 * branch            main       -> FETCH_HEAD
Merge made by the 'ort' strategy.
 README.md | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

手元のファイルとリモートのREADMEが、両方そろいました。履歴を見ると、2つのコミットがマージコミットでつながっています。

実行ログ
$ ls
README.md
app.py

$ git log --oneline --graph
*   0c7ed63 Merge branch 'main' of ../remote
|\  
| * 4c21aa3 Initial commit
* cb5c153 first commit

この後は、ふつうに git push origin main でリモートに送れます。

うまくいかないとき

  • 手元とリモートに同じ名前のファイル（例: どちらにも README.md がある）があると、マージのときに衝突（コンフリクト）します。この記事の環境ではファイル名が重ならなかったため、衝突の解消は実行して確かめていません。手順は Git の公式ドキュメント（git-merge の「HOW TO RESOLVE CONFLICTS」）をご確認ください。
  • つなぐ先のリポジトリを間違えていると、関係のないプロジェクトが混ざります。git remote -v で登録したURLを確かめてから実行してください。
  • pull のたびに --no-rebase を付けるのが手間な場合は、最初のエラーの hint にあるとおり、git config pull.rebase false で「pull はマージで合わせる」を既定にできます。この記事では設定を変えず、コマンドごとに指定して実行しました。
  • リベースで合わせたい場合（--rebase）は、関係のない履歴どうしでどう動くかをこの記事では確かめていません。迷ったら、この記事と同じマージの方法をおすすめします。
  • 次から GitHub でリポジトリを作るときは、READMEなどを追加せずに空のまま作ると、この状況になりません。

まとめ

fatal: refusing to merge unrelated histories は、共通のコミットがない2つの履歴をGitが自動で合わせないためのエラーです。つなぐ先が正しいことを確かめてから git pull --no-rebase origin main --allow-unrelated-histories を実行すると、この環境では2つの履歴がマージされました。
