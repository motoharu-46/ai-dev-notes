Node.jsで SyntaxError: Cannot use import statement outside a module が出たときの原因と直し方【実行して確認】

※本記事はアフィリエイト広告（PR）を含みます。

公開日 2026-11-07　更新日 2026-11-09　手順・エラー解決 / JavaScript

この記事の手順は 2026年11月6日 に下記の環境で実際に実行して確認しました。

結論：package.json の "type" が "commonjs" だと、import 文を使えません

Node.jsで SyntaxError: Cannot use import statement outside a module が出たら、そのファイルが「CommonJS（require を使う古い書き方）」として読まれています。この環境では、package.json に "type": "commonjs" があるとエラーになり、"type": "module" に変えると import 文がそのまま動きました。

実行ログ
$ npm pkg set type=module && npm pkg get type
"module"

$ node index.js
こんにちは、山田さん

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
Node.jsNode.js v22.23.4
npmnpm 10.9.9

Node.js のバージョンによって、package.json に "type" がないときの動きが違います（後で説明します）。お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：type が commonjs のプロジェクトで import を使う

関数を書き出す greet.js と、それを import して使う index.js を用意しました。

実行ログ
$ cat greet.js
export function greet(name) {
  return `こんにちは、${name}さん`;
}

$ cat index.js
import { greet } from "./greet.js";

console.log(greet("山田"));

package.json がない状態では、このNode.js 22ではそのまま動きました。

実行ログ
$ node index.js
こんにちは、山田さん

ここで npm init -y で package.json を作り、"type" を "commonjs" にして実行すると、エラーになりました。

実行ログ
$ npm init -y > /dev/null && npm pkg set type=commonjs && npm pkg get type
"commonjs"

$ node index.js
(node:1107) Warning: Failed to load the ES module: /home/dev/work/node-esm/index.js. Make sure to set "type": "module" in the nearest package.json file or use the .mjs extension.
(Use `node --trace-warnings ...` to show where the warning was created)
/home/dev/work/node-esm/index.js:1
import { greet } from "./greet.js";
^^^^^^

エラーの直前の Warning に、直し方の候補が2つ書かれています。「一番近い package.json に "type": "module" を書く」か、「拡張子を .mjs にする」です。

原因：.js ファイルを CommonJS として読んでいる

Node.jsの公式ドキュメントによると、.js ファイルをどちらの方式で読むかは、一番近い package.json の "type" で決まります。"commonjs" なら CommonJS として読むため、ES モジュールの書き方である import 文は使えません。

直し方：package.json の "type" を "module" にする

"type" を "module" に変えて、同じファイルを実行しました。

実行ログ
$ npm pkg set type=module && npm pkg get type
"module"

$ node index.js
こんにちは、山田さん

エラーが消えました。プロジェクト全体で import を使う場合は、この方法が一番手間がかかりません。package.json を1か所変えるだけで、ファイル名や中身は変えずに済みます。

うまくいかないとき

  • "type" を消した（書いていない）状態だと、このNode.js 22では動きましたが、次の警告が出ました。Node.js が中身を見て ES モジュールだと判断し、読み直したためです。警告をなくすには、警告にあるとおり "type": "module" を書きます。
実行ログ
$ npm pkg delete type && npm pkg get type
{}

$ node index.js
こんにちは、山田さん
(node:1165) [MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file:///home/dev/work/node-esm/index.js is not specified and it doesn't parse as CommonJS.
Reparsing as ES module because module syntax was detected. This incurs a performance overhead.
To eliminate this warning, add "type": "module" to /home/dev/work/node-esm/package.json.
(Use `node --trace-warnings ...` to show where the warning was created)
  • 古いバージョンのNode.jsでは、"type" がないと中身を見ずに CommonJS として読むため、package.json がなくても同じエラーになることがあります。この記事では Node.js 22 以外は実行して確かめていません。お使いのバージョンの動きは、Node.js 公式ドキュメントの「Modules: Packages」をご確認ください。
  • プロジェクトの他の部分が require を使っていて "type" を変えられない場合は、import を使うファイルだけ拡張子を .mjs にする方法もあります（エラー前の Warning に書かれている方法です）。

まとめ

SyntaxError: Cannot use import statement outside a module は、.js ファイルが CommonJS として読まれているときのエラーです。package.json の "type" を "module" にすると、この環境では import 文がそのまま動きました。
