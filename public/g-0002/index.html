結論：言語を1つ決めて手元で動かせる環境を作り、AIの答えを「自分で動かして確かめる」力から身につけます

生成AIに聞けばコードはすぐに出てきますが、そのコードが自分のパソコンで動くとは限りません。AIは、あなたが使っているOS、Pythonのバージョン、ファイルの置き場所、入れてあるパッケージを知らないまま答えを書くことが多いからです。そのため独学の最初の段階では、文法を暗記するよりも先に、「手元で実行できる環境を持つこと」「エラー文を自分で読めること」「出てきたコードを動かして結果を確かめること」の3つを身につけるのが近道になります。

最初の一歩は、学ぶ言語を1つに決め（迷ったら、業務の自動化にもAIの活用にも使われることの多い Python）、作業用のフォルダに仮想環境（venv）を作るところです。この記事では、その先を5つのステップに分け、各ステップで「できるようになること」「AIに頼るときの注意点」「このサイトの手順記事」を並べました。

全体の順番

ステップできるようになることこのサイトの手順記事
1. 手元で動かせる環境を作るvenv を作り、AIが勧めたパッケージを正しい場所に入れるModuleNotFoundError（venv）、externally-managed-environment
2. エラー文を自分で読むトレースバックから種類・説明・行番号を拾い、AIに渡す情報を選べる全角スペースの SyntaxError、IndentationError、NoneType の TypeError

ステップ1：手元で動かせる環境を作る

AIに「このコードを動かしたい」と聞くと、多くの場合「pip install ○○ を実行してください」という答えが返ってきます。ところが、その pip がどのPythonにパッケージを入れるのかは、環境によって変わります。パソコンに複数のPythonが入っていると、インストールは成功したのに実行すると ModuleNotFoundError になる、という食い違いが起きます。Ubuntu 24.04 などでは、仮想環境の外で pip install を実行すると、OSのPythonを守るためにエラーで止められます。

どちらも、作業フォルダに venv を作って有効にし、その中で pip install を実行し直すことで解決できることを、このサイトの手順記事で確かめています。AIの答えをそのまま貼り付ける前に、「今どのPythonで動いているか」を確認する習慣をこの段階でつけておくと、後のステップでのつまずきが減ります。

  • AIに頼るときの注意点: 環境を壊すおそれのあるオプション（OSのPythonに無理に入れる指定など）を勧められたら、仮想環境で済ませられないかを先に考えます。
  • つまずきやすい所: Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv）、pip install で error: externally-managed-environment が出たときの原因と直し方（Ubuntu 24.04）
  • 公式ドキュメント: https://docs.python.org/ja/3/tutorial/venv.html

ステップ2：エラー文を自分で読む

エラーが出たときに、画面に出た文字をすべてAIに貼り付けても、答えは返ってきます。ただ、何が起きたのかを自分で説明できないままだと、似たエラーが出るたびに同じことを繰り返すことになります。Pythonのエラー文（トレースバック）は、最後の行にエラーの種類と説明があり、その上にエラーが起きたファイル名と行番号が並ぶ形になっています。まずはこの3つを自分で拾えるようにします。

日本語で入力していると、目に見えない全角スペースが紛れ込んで SyntaxError になることがあります。インデントのずれによる IndentationError や、関数が値を返さずに None になったまま添字で読もうとして起きる TypeError も、書き始めのころに出会いやすいエラーです。どれも、エラー文の行番号を手がかりにすれば、AIに聞く前に自分で原因の行を見つけられます。

  • AIに頼るときの注意点: 質問するときは、エラー文の最後の数行と、該当する行の前後のコード、使っているPythonのバージョンを添えると、的外れな答えが減ります。
  • つまずきやすい所: Pythonで SyntaxError: invalid non-printable character U+3000 が出たときの原因と直し方（全角スペース）、Pythonで IndentationError: unexpected indent が出たときの原因と直し方、Pythonで TypeError: 'NoneType' object is not subscriptable が出たときの原因と直し方
  • 公式ドキュメント: https://docs.python.org/ja/3/tutorial/errors.html 、https://docs.python.org/ja/3/tutorial/index.html

ステップ3：AIのコードを動かして確かめる

AIが書いたコードは、AIが想定したフォルダ構成とファイルの場所を前提にしています。たとえば data.csv を開くコードは、スクリプトの置き場所ではなく、実行したときの作業フォルダを基準にファイルを探します。そのため、エディタの実行ボタンから動かすか、ターミナルの別のフォルダから動かすかで、同じコードが動いたり FileNotFoundError になったりします。

また、AIに「関数を別のファイルに分けて」と頼むと、2つのファイルがお互いを import し合う形になり、循環インポートの ImportError が出ることがあります。こうした「コード自体は正しそうなのに動かない」場面で、原因を見分けられるようになるのがこのステップの目標です。pathlib を使ってスクリプトの場所を基準にパスを組み立てる方法と、import の向きを一方通行にする考え方を、手順記事で実際に試して確かめています。

  • AIに頼るときの注意点: 動いたかどうかは、AIの説明ではなく、自分の環境で実行した出力で判断します。
  • つまずきやすい所: [Pythonで FileNotFoundError: [Errno 2] No such file or directory が出たときの原因と直し方（相対パスと実行場所）](/h-0009/)、Pythonで ImportError: cannot import name from partially initialized module（循環インポート）が出たときの原因と直し方
  • 公式ドキュメント: https://docs.python.org/ja/3/library/pathlib.html 、https://docs.python.org/ja/3/tutorial/modules.html

ステップ4：自分の作業を1つ自動化する

ここまで来たら、教材の例題ではなく、自分の毎日の作業から題材を1つ選びます。たとえば「毎月届くCSVを開いて、部署ごとに合計を出して別のファイルに保存する」といった、手作業だと時間がかかるけれど手順は決まっている作業が向いています。題材が自分のものだと、AIに聞く内容も具体的になり、返ってきたコードが正しいかどうかも、自分の知っている結果と見比べて判断できます。

日本語のCSVを扱うと、文字コードの違いで UnicodeDecodeError になることがあります。pandas では、見た目は同じ列名なのに KeyError になったり、絞り込んだ表に値を入れたときに SettingWithCopyWarning が出たりします。どれもAIに聞けば対処法は出てきますが、手順記事の実行ログと見比べながら、自分のデータで同じことが起きているかを確かめると理解が残ります。

  • AIに頼るときの注意点: 業務のデータをそのままAIに貼り付けず、列名だけを残したダミーのデータで質問します。
  • つまずきやすい所: Pythonで UnicodeDecodeError: 'utf-8' codec can't decode byte が出たときの原因と直し方（日本語CSV）、pandasで KeyError: '列名' が出たときの原因と直し方（列は存在するのに）、pandasで SettingWithCopyWarning が出たときの原因と消し方（.copy() と .loc）
  • Pythonで業務自動化まで進める順番を詳しく: Pythonを独学で業務自動化まで進める順番

ステップ5：変更を記録して戻れるようにする

AIの提案を次々に試していると、どこで動かなくなったのか分からなくなることがあります。Git でコードの変更を記録しておけば、動いていた時点に戻ったり、AIが書き換えた箇所だけを見比べたりできます。最初は、作業フォルダで git init を実行し、動いた時点で commit する、という最小限の使い方で十分です。

GitHub などにリポジトリを置くようになると、手元とリモートの履歴が別々に作られていて、git pull で refusing to merge unrelated histories と止められることがあります。このエラーが出る仕組みと直し方も、手順記事で再現して確かめています。

  • AIに頼るときの注意点: AIに大きな書き換えを頼む前に commit しておくと、結果が気に入らなくても元に戻せます。
  • つまずきやすい所: git pull で fatal: refusing to merge unrelated histories が出たときの原因と直し方
  • 公式ドキュメント: https://git-scm.com/book/ja/v2

独学で進めるか、スクールを使うか

生成AIに質問できるようになって、独学で調べられる範囲は以前より広がっています。この記事の5つのステップも、公式ドキュメントとこのサイトの手順記事、そしてAIへの質問を組み合わせれば、独学で進められるように並べています。

ただし、AIの答えが正しいかどうかを判断できないうちは、間違った説明をそのまま覚えてしまうこともあります。人に質問して、自分のコードを見たうえで答えてもらえる環境がほしい場合は、オンラインのプログラミングスクールも選択肢になります。このサイトではスクールを受講して確かめてはいないため、ここではリンクの紹介にとどめます。学べる内容や質問の受け付け方、料金などの条件は、申し込む前に各公式サイトで確認してください。

まとめ

AI時代の独学は、言語を1つ決めて手元の環境を作り、エラー文を自分で読み、AIのコードを自分の環境で動かして確かめる、という順に進めるのがおすすめです。そのうえで自分の作業を1つ自動化し、Git で変更を記録できれば、AIの提案を安心して試せるようになります。このページは、手順記事が増えるたびに表と本文を更新します。
