Pythonで IndentationError: unexpected indent が出たときの原因と直し方【実行して確認】

公開日 2026-11-08　更新日 2026-11-08　手順・エラー解決 / Python

この記事の手順は 2026年11月7日 に下記の環境で実際に実行して確認しました。

結論：字下げが不要な行に字下げが入っています。行頭のスペースを消すと直ります

IndentationError: unexpected indent は「ここで字下げ（インデント）が始まるはずがないのに、行の先頭にスペースがある」という意味のエラーです。コードを別の場所からコピーして貼り付けたときに起きやすく、エラー文の line に出ている行の先頭に余計なスペースがあります。この環境では、その行の先頭のスペースを消すと、プログラムが最後まで動きました。

sed -i '2,3s/^    //' sales.py
実行ログ
$ python3 sales.py
合計：500円、平均：166円

検証環境

項目バージョン
OSUbuntu 24.04.5 LTS
PythonPython 3.13.18

お使いの環境（OS・バージョン）が違うと、出力やエラー文が少し変わることがあります。

エラーの再現：貼り付けたコードの字下げがそのまま残っている

商品の合計と平均を計算する短いプログラムを用意しました。2行目と3行目は、関数の中から切り出して貼り付けたつもりで、先頭に半角スペースが4つ残っています。

実行ログ
$ cat sales.py
prices = [120, 80, 300]
    total = sum(prices)
    average = total // len(prices)
print(f"合計：{total}円、平均：{average}円")

実行すると、次のエラーになりました。

実行ログ
$ python3 sales.py
  File "/tmp/run-h-0005/sales.py", line 2
    total = sum(prices)
IndentationError: unexpected indent

エラー文の読み方は次のとおりです。

  • line 2 は、問題のある行の番号です。3行目も同じように字下げされていますが、Pythonは最初に見つけた1か所でエラーを出して止まるため、表示されるのは2行目だけです。
  • unexpected indent は「予期しない字下げ」という意味です。

原因：Pythonでは字下げが「ブロック」の区切りになっている

Pythonでは、行の先頭の字下げに意味があります。公式ドキュメント（字句解析）の説明では、字下げが深くなるのは if・for・def などの行末の : に続くブロックの中だけで、それ以外の場所で字下げが深くなると IndentationError になります。今回の2行目の前の行（prices = [120, 80, 300]）は : で終わっていないので、2行目を字下げする理由がありません。

行の先頭にスペースがある行は、grep で探せます。"^ " は「行の先頭が半角スペース」という意味です。

実行ログ
$ grep -n "^ " sales.py
2:    total = sum(prices)
3:    average = total // len(prices)

2行目と3行目が見つかりました。どちらも、ブロックの中ではないのに字下げされている行です。

直し方：余計な字下げを消して、前の行と先頭をそろえる

エディタで2行目と3行目の先頭のスペースを消し、1行目と同じ位置から書き始めるようにします。ここでは、同じことをコマンドで行いました。sed -i '2,3s/^ //' は「2〜3行目の先頭にある半角スペース4つを消す」という意味です。

実行ログ
$ sed -i '2,3s/^    //' sales.py

$ cat sales.py
prices = [120, 80, 300]
total = sum(prices)
average = total // len(prices)
print(f"合計：{total}円、平均：{average}円")

$ python3 sales.py
合計：500円、平均：166円

エラーが消えて、合計と平均が表示されました。大事なのは、字下げを消す行を「本来はブロックの外にある行」に限ることです。for や if の中身として字下げしてある行まで消すと、今度は別のエラーになったり、意図と違う動きになったりします。

うまくいかないとき

  • 字下げを戻すときに、深さが前の行とそろっていない場合は、unexpected indent ではなく unindent does not match any outer indentation level というエラーになりました。次の例では、5行目の return を半角スペース2つで書いています。関数の中身は半角スペース4つで字下げしているので、2つではどのブロックの深さとも合いません。
実行ログ
$ cat func.py
def total_price(prices):
    total = 0
    for p in prices:
        total += p
  return total

print(total_price([120, 80, 300]))

$ python3 func.py
  File "/tmp/run-h-0005/func.py", line 5
    return total
                ^
IndentationError: unindent does not match any outer indentation level

return の先頭を半角スペース4つにして、total = 0 と同じ深さにそろえると動きました。

実行ログ
$ sed -i '5s/^  return/    return/' func.py

$ cat func.py
def total_price(prices):
    total = 0
    for p in prices:
        total += p
    return total

print(total_price([120, 80, 300]))

$ python3 func.py
500
  • 見た目はそろっているのに、タブとスペースが混ざっている場合は、TabError: inconsistent use of tabs and spaces in indentation になりました。エディタによってはタブがスペース4つ分の幅で表示されるため、画面では違いが分かりません。cat -A で表示すると、タブは ^I、行末は $ として見えます。
実行ログ
$ cat tab.py
def average(prices):
    total = sum(prices)
	return total // len(prices)

print(average([120, 80, 300]))

$ python3 tab.py
  File "/tmp/run-h-0005/tab.py", line 3
    	return total // len(prices)
    ^
TabError: inconsistent use of tabs and spaces in indentation

$ cat -A tab.py
def average(prices):$
    total = sum(prices)$
^Ireturn total // len(prices)$
$
print(average([120, 80, 300]))$

3行目だけがタブ（^I）で字下げされていました。タブを半角スペース4つに置き換えると動きました。

実行ログ
$ sed -i 's/\t/    /' tab.py

$ cat -A tab.py
def average(prices):$
    total = sum(prices)$
    return total // len(prices)$
$
print(average([120, 80, 300]))$

$ python3 tab.py
166
  • 字下げは半角スペース4つにそろえるのが、Pythonの公式スタイルガイド（PEP 8）の推奨です。エディタにタブを自動でスペースに変える設定があれば、使うと混ざりにくくなります。設定の方法は、お使いのエディタの公式ドキュメントをご確認ください。
  • 字下げに全角スペースが入っている場合は、IndentationError ではなく SyntaxError: invalid non-printable character U+3000 になります。直し方は関連記事にまとめています。

まとめ

IndentationError: unexpected indent は、ブロックの中ではない行に字下げが入っているときのエラーです。エラー文の行番号で場所を確かめ、その行の先頭のスペースを消して前の行と書き始めの位置をそろえると、この環境ではプログラムが動きました。似たエラーの unindent does not match は字下げの深さのずれ、TabError はタブとスペースの混在が原因でした。

この手順の次に読む記事

  • Pythonで SyntaxError: invalid non-printable character U+3000 が出たときの原因と直し方（全角スペース）
  • Pythonで ModuleNotFoundError: No module named が出たときの原因と直し方（venv）
